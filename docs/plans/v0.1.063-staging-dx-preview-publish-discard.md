## 3. 機能別設計

### Feature 1: 下書きプッシュ成功時の Admin / Preview URL 出力 ＆ `emit preview [target]`

- **Layer 0 (`src/client/endpoints.ts`)**:
  - §1.1 の確認完了後、`articleAdminEndpoint(origin: string, collection: string, id: string): string`（および公式 API があれば `articlePreviewEndpoint`）を追加する。
- **Layer 2 (`src/sync/push/types.ts`, `src/sync/push/commit.ts`)**:
  - `PushResult` に `adminUrl?: string`, `previewUrl?: string`, `hasDraftRevision?: boolean` を追加。URL 仕様未確認の項目は `undefined` のまま返し、推測値を設定しない。
- **Layer 3 (`src/cli/commands/push.ts`, `src/mcp/tools/sync-push.ts`, `src/cli/commands/preview.ts`)**:
  - `emit push`（単体 / `--all`）および MCP `sync_push` で `adminUrl` / `previewUrl` が存在する場合のみ `🛠️ Admin: <url>` / `🔗 Preview: <url>` を出力する。
  - 新規コマンド `emit preview [target]`（`<file>` または `<ULID>`、`--no-open` で URL 出力のみ）を登録。ターゲット解決には既存ヘルパーを再利用し、ブラウザ起動コマンド（`open` / `xdg-open`）はテスト注入可能にする。

### Feature 2: ステージ済み下書きの本番昇格 `emit publish <target>` ＆ MCP `sync_publish`

- **目的**: 既にリモートにステージされている下書き（`published*` または `draft`）を、コンテンツ再送信なしで即座に本番公開する。
- **必須の安全ガード**:
  1. **ローカル未プッシュ変更ブロック（`UNPUSHED_CHANGES_PROTECTION`）**: `!isLocalFileUnmodified(...)` または本文・`featuredImage` に未アップロードの `media/drafts/` 参照が残っている場合は即ブロックし、`emit push <file> --allow-publish` を案内する。
  2. **保留フラグブロック**: `conflict_pending` / `delete_pending`（G15）/ `taxonomy_conflict_pending`（G16）/ `taxonomy_apply_pending`（G17）がある場合はブロック。
  3. **リモート変更ブロック（新設 Guard G22: `REMOTE_CHANGED_BEFORE_PUBLISH`）**: `GET` で取得した `comparisonRev` と `sync_state.remote_rev` が一致しない場合（前回同期以降に Web 画面等でリモート下書きが更新された場合）、古いローカル本文のまま `status: published` へ切り替わって `emit status` / `diff` で `local changed` 齟齬が生じるのを防ぐためブロックし、`emit pull` での最新化を促す。
- **実行フロー（`orchestrator.ts: publishArticle`）**:
  1. `<file>` または `<26-char ULID>` から対象記事と `sync_state` を解決。
  2. `GET /_emdash/api/content/{collection}/{id}` で最新 `_rev`（Track 1）と `comparisonRev`（Track 2）を取得し、上記ガード 1〜3 を検証。既に `status === 'published'` かつ `draftRevisionId === null` の場合は no-op として通知。
  3. 7 分分散ロックを取得し、`transitionContentStatus(..., 'published', ...)`（`POST .../publish`）を実行してロック解放。
  4. **Two-Track / Two-Layer 同期 & ディレクトリ移動**: `extractComparisonRev` で `sync_state.remote_rev` を `@live:...` へ更新し、`commitArticleSnapshot` 経由でディスク上のフロントマターを `status: published`（`# draft revision` コメント除去）に更新する。**元が `status: draft` だった記事は `commitArticleSnapshot` の正規パス計算により `posts/draft/` → `posts/published/` へ移動（旧ファイル unlink）される**。
- **CLI / MCP 対称性**:
  - CLI: `emit publish <target> [-p, --profile <name>]`
  - MCP: `sync_publish`（`target`: filePath or ULID）— `withResolvedContext()` 経由で `_meta` 付与。

### Feature 3: ステージ済み下書きの破棄・ロールバック `emit discard-draft <target>` ＆ MCP `sync_discard_draft`

- **目的**: 公開中記事にステージされた未公開下書き（`published*`）をリモートから破棄し、ローカルファイルと `cache.db` を公開中の本番バージョンへ戻す。
- **必須の安全ガード**:
  1. **対象限定（新設 Guard G21: `DRAFT_ONLY_DISCARD_FORBIDDEN`）**: 「公開済み記事の未公開下書き（`status === 'published'` かつリモートに `draftRevisionId` が存在）」のみを対象とする。公開版を持たない `status: draft` 記事への実行は禁止し、`emit delete` を案内する。
  2. **ローカル未プッシュ編集の保護（`UNPUSHED_CHANGES_PROTECTION`）**: `!isLocalFileUnmodified(...)` の場合、デフォルトでブロックする（`--force` 指定時は `quarantineLocalCopy()` で `posts/conflicts/` へレスキュー退避してから続行）。
- **実行フロー（`orchestrator.ts: discardDraftArticle`）**:
  1. `GET` で最新 `_rev`・`status`・`draftRevisionId` を確認（G21 検証、`draftRevisionId === null` なら no-op 案内）。
  2. 7 分分散ロックを取得し、`POST /_emdash/api/content/{collection}/{id}/discard-draft` を実行してロック解放。
  3. 直後に `pullArticle`（本番データ取得）を実行し、ローカルファイルと `cache.db` を `🟢 [synced] published` 状態へ同期する。
  4. **中間失敗時のリカバリ案内**: リモート `discard-draft` が成功した後に再 `pullArticle` が通信等で失敗した場合は、「リモート上の下書きは既に破棄済みです。ネットワーク等を確認のうえ `emit pull <id>` を実行してローカルを同期してください」と明示的に案内する。
- **CLI / MCP 対称性**:
  - CLI: `emit discard-draft <target> [-f, --force] [-p, --profile <name>]`
  - MCP: `sync_discard_draft`（`target`, `force?`）— `withResolvedContext()` 経由で `_meta` 付与。
