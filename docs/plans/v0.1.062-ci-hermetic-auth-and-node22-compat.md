- **対象バージョン**: `v0.1.62`
- **作成日**: 2026-11-25
- **ステータス**: **Draft（承認待ち）**
- **前提**: `v0.1.61`（`9477bba`）の GitHub Actions CI（`ubuntu-26.04`, Node `v22.23.5`）において、7 ファイル 12 テストが失敗（ローカル macOS / Node `v26.11.1` では全件パスしていた）。

## 1. 失敗 12 件の切り分け結果

CI 失敗は次の 2 系統に明確に分離される。

### 系統 1（7 件 — ローカル再現済み・原因確定）: ローカル `~/.config/emit/profiles.yaml` への暗黙依存

`HOME=$(mktemp -d) npx vitest run` を実行することで、CI と完全に同一のエラー 7 件をローカルで再現確認済み：

| テストファイル | 失敗テスト | エラー内容 |
| --- | --- | --- |
| `tests/article_search.test.ts:520` | `T7: MCP sync_article_search returns snapshotStatus framing...` | `SyntaxError: Unexpected token '❌', "❌ No authe"...` |
| `tests/mcp.test.ts:1023` | `registers sync_snapshot and supports status, clear, and sync_status...` | 同上 |
| `tests/status_unpublished_draft.test.ts:194` | `transparents hasUnpublishedDraft in MCP sync_status tool response` | 同上 |
| `tests/cli.test.ts:1345` | `T10: resolves pull article target by filePath or ID...` | `❌ Error: No authentication found.`（`[ARTICLE_TARGET_UNRESOLVED]` に到達せず） |
| `tests/cli.test.ts:1461` | `routes status and diff profile resolution errors through reportActionFailure...` | `❌ Error: No authentication found.`（`nonexistent-profile-xyz` エラーに到達せず） |
| `tests/cli.test.ts:1549` | `supports argument-less emit diff...` | `process.exit unexpectedly called with "1"`（`No authentication found`） |
| `tests/cli.test.ts:1593` | `supports readConfirmLine I/O injection... argument-less emit push` | 同上 |

**根本原因**:
1. `tests/setup/env-isolation.ts` が `EMDASH_*` 環境変数を削除しているものの、**`HOME` / `XDG_CONFIG_HOME`（`~/.config/emit/profiles.yaml`）を隔離していない**。そのため開発機では `~/.config/emit/profiles.yaml` が暗黙に読まれ、クリーン環境（CI）での認証欠落を検知できていなかった。
2. 上記 7 テスト自体も、`EMDASH_TOKEN` やテスト用 `profilesPath` を明示設定せずに実行していた。

### 系統 2（5 件 — **環境固有ではなく時刻依存の flaky テスト**）: ファイル名の `yyyyMMdd_` プレフィックスと remote 日付の不整合

> [!IMPORTANT]
> **Rev.2 訂正**: 「Ubuntu / Node 22 環境でのみ発生」という当初見立ては誤り。原因は OS / Node バージョンではなく、**テスト実行時刻（ローカルタイムゾーンの午前0時をまたぐ実行）** である。CI 実行は `2026-11-24T06:06Z` = **JST 11/25 01:36（日付跨ぎ）**。macOS ローカルでの再実行はいずれも JST 午前7時台＝同一日付のため再現しなかった。Node バージョン・Linux/macOS は無関係。

失敗はすべて「pull が実際に書き込むファイル名（`<yyyyMMdd>_<ulid>-<title>.md`）」と「テストが期待する固定パス」の不一致であり、**タイトルサニタイズや `node:sqlite` の差異ではない**（remote 側の `data.title` は slug と同一なので sanitize 結果も一致する）。

| テスト | 期待パス | pull が実際に書くパス | 不整合の理由 |
| --- | --- | --- | --- |
| `local_media_refs.test.ts:980` (T4) | `20261124_...-fast-heal.md`（`formatDatePrefix(new Date())`） | `posts/draft/01M67LQCALREF556YVG6RBT0J0.md` | `sync_state` に ULID を含まない固定パス（`posts/draft/article.md`）を保存しているため、`findLocalFilesByUlid` も `extractDatePrefixFromPath` も失敗 → 日付プレフィックスなしのフォールバック名 |
| `pull_pruning.test.ts:167` | 同一 ULID のファイルが残存 | **art1/art2 が prune 対象になる**（`result.deleted === 1` は art3 のカウントで通過） | `setupLocalArticle` が ULID を含まない `computeArticleRelativePath(...)` を保存 → `sync_state.localFilePath` に ULID なし → remote 側の title（slug と同一文字列） sanitize で別名が算出され、disk 上のファイルが見つからず unlink |
| `pull_draft_revision.test.ts:133, 303, 429` | `20261114_...-draft-rev-test.md` | `20261125_...`（実行当日） | fixture の remote payload に `publishedAt` / `createdAt` が**無く** `updatedAt: '2026-11-14T...'` のみ。`resolveCanonicalArticlePath` は `publishedAt → existingPrefix → createdAt → updatedAt` の順で、`existingPrefix` が ULID 非包含の tracked path から復元できないため当日日付にフォールバック |

**なぜ CI だけ / なぜ JST 深夜だけ落ちるか**

- 上記 3 テストはいずれも `sync_state.localFilePath` に **26 文字 ULID を含まないパス**を保存している（`article.md` / slug 由来名）。ULID を含む既存ファイル名があれば `findLocalFilesByUlid` が日付プレフィックスを復元するため、時刻依存性は表面化しない。
- JST の当日日付が fixture の固定日付（20261114）と一致する時間帯＝**JST 0:00〜9:59 のうち UTC と同一カレンダー日付の 0:00〜8:59** に実行した場合のみ、`updatedAt` から算出したプレフィックスが `20261114` と一致してテストがパスする。CI の 01:36 はこれに該当せず、macOS での再実行（07:xx）は当日日付同士で一致した。
- ローカル再現: `TZ=America/Los_Angeles npx vitest run tests/pull_draft_revision.test.ts` → 6 件中 1 件が別パターン（`healed` が `undefined`）で失敗。時刻・タイムゾーンを振ると**どの OS / Node でも**系統 2 と同種の破綻が起きることを確認済み。

## 2. 修正方針（2 段階）

### Phase A: テスト環境の完全隔離 & 系統 1（7 件）の修正

1. **`tests/setup/env-isolation.ts` の強化**:
   - 各テストワーカーのプロセス起動時に一時 `HOME`（例: `os.tmpdir()` 配下の隔離ディレクトリ、または存在しないパス）または `EMDASH_PROFILES_PATH` 未設定隔離を適用するか、`tests/setup/env-isolation.ts` で存在しない隔離ホームディレクトリを割り当てて開発者の `~/.config/emit/profiles.yaml` への暗黙フォールバックを構造的に遮断する（既存の `tests/profile.test.ts` 等、意図的に `HOME` / `profilesPath` をテストする箇所が壊れないことも全件確認する）。
2. **系統 1 の 7 テスト修正**:
   - **MCP テスト 3 件**（`tests/article_search.test.ts`, `tests/mcp.test.ts`, `tests/status_unpublished_draft.test.ts`）: `createMcpServer({ workspaceRoot: tempDir, ..., profilesPath })` にテスト用の一時 `profiles.yaml`（または `EMDASH_TOKEN`）を設定し、開発者の `HOME` に依存しない構成へ修正。
   - **CLI テスト 4 件**（`tests/cli.test.ts`）: `tempDir` にテスト用プロファイル（`profilesPath` / `EMDASH_TOKEN`）を設定し、`pull` / `status` / `diff` / `push` が認証前エラーではなく本来の分岐（`[ARTICLE_TARGET_UNRESOLVED]`、`nonexistent-profile-xyz`、`diff` / `push` ガード）へ到達するようにする。
3. **検証**: `HOME=$(mktemp -d) npm run check` がローカルで **77 files / 全テストグリーン** になることを実証する。

### Phase B: 系統 2（5 件）の恒久修正 — **日付・時刻への依存を除去する**

環境再現ではなく、テスト fixture の時刻依存そのものを除去する（`src/` の変更は不要と判断）。

1. **`tests/pull_pruning.test.ts`**: `setupLocalArticle` が保存する `relPath` を、標準命名 `<yyyyMMdd>_<ULID>-<slug>.md` に統一する（ULID を文件名に含むため `findLocalFilesByUlid` / `extractDatePrefixFromPath` が機能し、remote title sanitize との一致問題も消える）。あわせて remote payload の `data.title` を slug と明示的に同一にして sanitize 差異をなくす。
2. **`tests/pull_draft_revision.test.ts`**: fixture の remote payload に `publishedAt` / `createdAt`（fixture の固定日付と同一）を追加し、`resolveCanonicalArticlePath` が実行当日ではなく fixture 日付でプレフィックスを決定するようにする。または tracked path を ULID 包含の正しい命名に修正して `existingPrefix` 経路を通す。
3. **`tests/local_media_refs.test.ts` (T4)**: 事前 `sync_state.localFilePath` / disk パスを ULID 包含の標準命名へ修正し、期待パスを `result.filePath`（pull が返す実際の canonical path）基準に置き換えて日付計算依存を撤去する。
4. **回帰防止**: 3 ファイルに「実行時刻に依存しない」ことを示すコメントを追加。可能であれば `tests/` に UTC 固定ではなく**プレフィックスの実値比較**（`expect(diskPath).toMatch(/^(\\d{8}_)?<ulid>-/)`）を導入し、日付ハードコードを禁止する。
5. **検証**: 少なくとも 2 つのタイムゾーンで振って全件グリーンを確認する。
   ```bash
   TZ=Asia/Tokyo npx vitest run tests/pull_pruning.test.ts tests/pull_draft_revision.test.ts tests/local_media_refs.test.ts
   TZ=America/Los_Angeles npx vitest run tests/pull_pruning.test.ts tests/pull_draft_revision.test.ts tests/local_media_refs.test.ts
   ```
   （`TZ=America/Los_Angeles` では `tests/pull_draft_revision.test.ts` の `heals missing # draft revision ...` が別パターンで失敗するため、このケースも併せて fixture 日付を明示固定する。）

> [!NOTE]
> **Docker / Node 22 コンテナ再現は不要**。Node バージョンに起因する証拠は無いため、Phase B のために Linux / Node 22 環境を用意しない（CI 自体が ubuntu-26.04 / Node 22 で検証環境を兼ねる）。

## 4. Ask First 確認事項

- Phase A はテストコードのみの変更のためカテゴリ 1〜4 への該当なし。ただし `tests/setup/env-isolation.ts` で `HOME` を差し替える場合、`os.homedir()` は `process.env.HOME` に追随しないため `vi.spyOn(os, 'homedir')` 相当の固定が別途必要（v0.1.38 の教訓）。MCP ハートビート（`src/utils/mcp-heartbeat.ts`）は `process.env.HOME` を先に読むため、`HOME` 隔離だけで `mcp_state.json` も分離できる。
- Phase B はテスト fixture のみで完結し、`src/` 変更・Public Facade / Layering Allowlist 変更は発生しない（カテゴリ 3 に該当しない）。
