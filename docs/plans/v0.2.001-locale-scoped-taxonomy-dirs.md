# v0.2.0 追加実装計画書: タクソノミー定義ディレクトリのロケール別分割（`categories/<locale>/`・`tags/<locale>/`）

- **対象バージョン**: `v0.2.0`（既存の `v0.2.0` コミットへ統合）
- **作成日**: 2026-11-27
- **前提**: EmDash 1.4 以降をサポート対象とし、タクソノミー（カテゴリ・タグ）にも `locale` が存在する前提で、記事（`posts/<locale>/{draft,published}/`）と対称なディレクトリ構造へ統一する。
- **ステータス**: 実装済み（2026-11-27、`v0.2.0` 統合）

---

## 1. 背景と目的

`v0.2.0` にて記事の配置を `posts/<locale>/{draft,published}/` へ刷新した一方、タクソノミー定義は `categories/*.yaml` および `tags/*.yaml` のフラット配置のまま残っていた。
しかし EmDash 1.4 以降ではカテゴリ・タグ自体も `locale` と `translationGroup` を持つため、フラット配置では人間・AI エージェントがディレクトリを見た際に「どの言語用のカテゴリ／タグか」を直感的に判別しにくい。

本追加実装では、**`categories/<locale>/*.yaml`** および **`tags/<locale>/*.yaml`** を正規構造として統一し、ワークスペース全体の Multi-Language First 構造を完結させる。

```text
workspace/
├── posts/
│   ├── ja/{draft,published}/
│   ├── en/{draft,published}/
│   └── conflicts/
├── categories/
│   ├── ja/*.yaml
│   └── en/*.yaml
├── tags/
│   ├── ja/*.yaml
│   └── en/*.yaml
└── media/
```

## 2. 設計詳細

### 2.1 書き込みと旧フラットファイルの自動削除（`src/sync/taxonomies.ts`）

- **`writeAndPruneTaxonomyDir()`**:
  - 各タームの `locale` を正規化して決定する（`item.locale?.trim().toLowerCase()`。欠落時は `params.defaultLocale || 'ja'` にフォールバックしつつ、`PullTaxonomiesResult.warnings` に警告を記録して観測可能にする — Layer 1 の `console.log` 禁止制約に準拠）。
  - 保存先を `path.join(params.dir, termLocale, `${item.id}-${sanitized}.yaml`)` とし、必要な `<locale>/` サブディレクトリを自動作成する。
  - 既存の `.yaml` 削除（prune）処理では、以下を走査・クリーンアップする：
    1. **`params.dir` 直下の全 `.yaml` ファイル**（旧フラット配置からの自動移行・掃除）
    2. **`params.dir/<locale>/` 配下のうち、今回の `activePaths` に含まれない `.yaml` ファイル**
    3. prune 後に空になった `<locale>/` サブディレクトリを削除する。
  - これにより、既存の `categories/*.yaml`・`tags/*.yaml` を手動削除しなくても、次回の `emit pull`（バッチ）実行時に自動で `<locale>/` 配下へ移行する。

### 2.2 読み込みと prune の非対称性（`src/sync/taxonomies.ts`）

- **`readTaxonomyDir(dir: string)`**:
  - `dir/<locale>/*.yaml`（1階層の非隠しサブディレクトリ内 `.yaml`）を走査して読み込む。
  - あわせて `dir/*.yaml`（直下に置かれたテスト用・手書きフィクスチャ）も引き続き透過的に読み込むことで、既存の単体テストフィクスチャとの互換性を損なわない。
  - **非対称性の仕様**: 直下の `*.yaml` は「読み取り専用互換として読めるが、次の正常な `pullTaxonomies()`（fetch 成功時）で prune されて `<locale>/` 配下へ正規化される」。この挙動をテストでも明示検証する。
  - 1ファイルから読み込んだ `locale` が未記載で、親ディレクトリ名（`<locale>`）から推定可能な場合は、そのサブディレクトリ名を `locale` として補完する（`yaml` 内の `locale:` が常に優先）。

### 2.3 CLI / MCP / ドキュメント / 静的ゲート同期

- **CLI / MCP メッセージ・説明文**:
  - `src/mcp/tools/sync-pull.ts`: `categories/<locale>/<id>-<name>.yaml`、`tags/<locale>/<id>-<name>.yaml`
  - `src/mcp/tools/sync-new.ts`: `categories/<locale>/*.yaml`、`tags/<locale>/*.yaml`
  - `src/mcp/server.ts` (`EMIT_MCP_INSTRUCTIONS`): `categories/<locale>/<id>-<name>.yaml`、`tags/<locale>/<id>-<name>.yaml`
  - `src/sync/new.ts`: 未知タクソノミー警告メッセージの表記を `categories/<locale>/*.yaml` / `tags/<locale>/*.yaml` へ更新（該当警告を検証する `tests/new_scaffold.test.ts` も同期）。
- **ドキュメント・ルール同期**:
  - `AGENTS.md`
  - `docs/taxonomies-and-bylines.md`
  - `docs/sync-engine-and-revisions.md`
  - `docs/safety-guards-and-diagnostics.md`
  - `docs/cli-and-mcp-reference.md`
  - `CHANGELOG.md`（`v0.2.0` セクションへ追記）
- **静的ゲート（`tests/layout_string_sync.test.ts`）**:
  - スキャン対象に `src/sync/new.ts` および `src/sync/taxonomies.ts` を追加し、ユーザー／AI 向け出力に旧フラット表記 `categories/*.yaml`・`tags/*.yaml`・`categories/<id>-`・`tags/<id>-` が残存しないことを検証する。
