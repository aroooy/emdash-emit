## 1. 背景と設計原則（`pull-media` ⇔ `push-media` の対称性）

現行（`v0.1.51`）の Emit では：

1. **画像単体のアップロード入口がない**: `uploadMediaFile()`（`src/client/media.ts:709`）と `promoteDraftMediaFile()`（`src/sync/media/mirror_item.ts:226`）は実装済みだが、記事の `emit push` 内部（`src/sync/push/media_stage.ts`）からしか呼ばれない。
2. **既存メディアの `alt` / `caption` 更新入口がない**: `PUT /_emdash/api/media/{mediaId}` を叩く `syncRemoteMediaMetadata()`（`src/client/media.ts:259`）は新規アップロードの `confirm` 直後（`:684`）にしか呼ばれず、ローカルの `media/<stem>.yaml` を編集してもリモートへ反映する手段がない。
3. **Dedup ヒット時に `alt` / `caption` が反映されない**: ローカルキャッシュ再利用（`resolveReusableUpload()` `:452`）およびサーバー側 `contentHash` 重複ヒット（`finalizeServerDedupHit()` `:515`）の経路で `syncRemoteMediaMetadata()` が呼ばれていない。

`v0.1.52` では、記事の `emit pull` ⇔ `emit push` と同じメンタルモデルで、**新規画像アップロード**と**既存メディアのメタデータ更新（フラグ指定 & ローカル YAML 編集反映）**を単一の **`emit push-media`**（MCP: **`sync_push_media`**）に統合する。

## 2. 詳細設計仕様

### 2.1 `<target>` の 3 モード自動判別と Two Media ID Spaces 解決（`src/sync/media/push_media.ts`）

`pushMedia(options: PushMediaOptions): Promise<PushMediaResult>` は 1 件以上の `targets: string[]` を受け取り、各 `target` を以下の順序で厳密に分類・実行する：

| 優先順                                                                       | `<target>` の種別                                                                           | 判定条件                                                                                                     | 実行アクション                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Mode A: ローカル companion YAML によるメタ更新**                           | `media/<stem>.yaml`                                                                         | `absPath` が実在し `.yaml` で終わる（`media/` 配下かつ `legacy_*.yaml` でないことを検証）                    | `.yaml` 内の `id:` から 26 文字 D1 `mediaId` を取得（`toMediaRecordId` 検証）。<br>• `--alt` / `--caption` 指定時：指定値でリモート `PUT /_emdash/api/media/{mediaId}` を更新し、ローカル `.yaml` の他フィールド（`id`, `filename`, `mimeType`, `size`, `width`, `height`, `storageKey`, `contentHash`, `status`, `url`, `createdAt`）を保持したまま `alt` / `caption` のみマージ書き戻しする。<br>• フラグ未指定時：**ローカル `.yaml` の `alt` / `caption`（文字列、空文字 `""` クリア含む）を読み取ってリモートへ `PUT`** する。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Mode B: ローカル画像ファイルのアップロード（または既存ミラーのメタ更新）** | `media/drafts/<file>`, 任意パス `~/Photos/a.jpg`, または `media/<stem>.<ext>`               | `absPath` が実在する通常ファイル                                                                             | • **B-1（決定論的ルーティング — 既存ミラー画像）**: `absPath` が `<workspaceRoot>/media/` 直下（`media/drafts/` を除く）にあり、かつ同ステムの `media/<stem>.yaml` に有効な 26 文字 `id:`（`mediaRecordIdForStem(mediaDir, stem) !== null`）が存在する場合は、**常にメタデータ更新（Mode A と同一処理）にルーティング**する（再アップロードは行わない）。<br>• **B-2（新規・未登録画像ファイル：`media/drafts/*` やワークスペース外パス、または companion `.yaml` 無しの画像）**:<br> 1. Layer 1 `probeLocalImageFile(absPath, filename)` でファイル種別・拡張子（`.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`, `.avif`, `.svg`）・50 MiB 上限を事前検証。<br> 2. `uploadMediaFile()` で 4 フェーズアップロード（または dedup 再利用）＋ `alt`/`caption` 反映。<br> 3. `promoteDraftMediaFile()` で `media/<markdownRef>.<ext>` + `.yaml` を生成し、`cache.saveMediaState({ ..., status: 'ready' })` を記録。<br> 4. **元ファイル保護**: ソースが `<workspaceRoot>/media/drafts/` 配下のときのみ `removeDraft: true`（移動）、それ以外の任意パスは `removeDraft: false`（元ファイルを残して `media/` へコピー）。 |
| **Mode C: `<mediaId>` または `<storageKey>` 指定によるメタ更新**             | 26 文字 ULID（`mediaId`）または R2 `storageKey`（`<ulid>.<ext>` / `<ulid1>.<ulid2>.<ext>`） | `absPath` が実在せず、かつ明示ファイルパス接頭辞（`./`, `../`, `/`, `~/`, `media/`, `.yaml` 末尾）を持たない | **Two Media ID Spaces の逆引き解決（Invariant 3）**:<br>• `PUT /_emdash/api/media/{mediaId}` は D1 レコード ID（`mediaId`）のみを受け付けるため、入力が `storageKey` の場合はそのままエンドポイントへ渡してはならない。<br>• 解決順序：<br> 1. `toMediaRecordId(target)` が非 null の場合：`mediaId` として確定し、`cache.getMediaStateByMediaId(mediaId)` または `media/*.yaml` からローカル companion YAML を探索。<br> 2. `toStorageKey(target)` が非 null の場合：`cache.getMediaState(storageKey)` または `collectLocalMirrorIndex(workspaceRoot, cache)` の companion YAML `id:` から D1 `mediaId` を逆引きする。ローカルに未ミラーの場合は `collectRemoteStorageKeys()` でリモート一覧から `storageKey` に対応する `mediaId` を解決する。<br>• `--alt` / `--caption`（またはローカル companion YAML が存在する場合はその `alt` / `caption`）を `PUT /_emdash/api/media/{mediaId}` へ送信し、ローカル companion YAML が存在する場合は書き戻す（ローカル YAML が無く `--alt` / `--caption` も未指定の場合は明示エラー）。                                                                                |

> **タイポされたファイルパスの誤判定防止**: `toStorageKey()`（`src/utils/media-id.ts:73`）は移行コーパス互換のためスラッシュを含む画像パスも受理する。したがって、`./`・`../`・`/`・`~/`・`media/` で始まる引数や `.yaml` で終わる引数がディスク上に存在しない場合は Mode C にフォールスルーさせず、即座に `MISSING_LOCAL_IMAGE_FILE`（または `MEDIA_COMPANION_NOT_FOUND`）エラーとして報告する。

### 2.2 クライアント層のメタデータ更新強化（`src/client/media.ts`）

1. **Dedup ヒット時の `alt` / `caption` 同期修正（要望の不整合解消 & Last-Writer-Wins 明文化）**:
   - 現在 `syncRemoteMediaMetadata()` は `confirmUpload()`（`src/client/media.ts:684`）でのみ呼ばれている。
   - ローカル `media_state` 再利用経路 `resolveReusableUpload()`（`:452`）およびサーバー側 dedup ヒット経路 `finalizeServerDedupHit()`（`:515`）においても、`options.alt?.trim()` または `options.caption?.trim()` が非空で指定されている場合は `syncRemoteMediaMetadata()` を呼び出すよう修正する（**両方未指定または空文字の場合は `PUT` を一切呼ばない 0-PUT を保証**）。
   - ※ 同一バイナリ画像を複数記事や `push-media` で再利用しつつ新しい非空 `alt` / `caption` を指定した場合、共有メディアレコードのメタデータは **Last-Writer-Wins（後勝ち）** で更新されることを `docs/media-pipeline.md` に明記する。
2. **明示的メタデータ更新用の厳密関数 `updateRemoteMediaMetadata()` の新設（EmDash スキーマ準拠）**:
   - EmDash サーバー側の `PUT /_emdash/api/media/{id}`（`media_update` OpenAPI/JSON Schema）では `alt`・`caption` ともに `{"type": "string"}`（`minLength` 制約なし、非 nullable）として定義されていることを確認済み。したがって空文字クリアには `null` ではなく **`""`（空文字列）** を送信する。
   - 記事 push 中のベストエフォート関数 `syncRemoteMediaMetadata()`（非空のみ送信・エラー握りつぶし）は維持したまま、明示的な `push-media` Mode A/B-1/C 用に `updateRemoteMediaMetadata(mediaId: MediaRecordId, metadata: { alt?: string; caption?: string }, options)` をエクスポートする：
     - `metadata.alt !== undefined` の場合は `body.alt = metadata.alt.trim()` を送信（**`--alt ""` や YAML の `alt: ""` による既存値の空文字 `""` クリアを許容**）。
     - `metadata.caption !== undefined` の場合は `body.caption = metadata.caption.trim()` を送信（空文字 `""` クリアを許容）。
     - `createAuthedFetch(options)` を使用し、HTTP エラー時は握りつぶさず `ApiError`（`code: 'MEDIA_METADATA_UPDATE_FAILED'`, `status`, `endpoint`）をスローする。

### 2.3 CLI / MCP インターフェース仕様

#### 1. CLI: `emit push-media`（`src/cli/commands/media.ts` に `registerPushMediaCommand` を追加、`src/bin/emit.ts` で登録）

```bash
emit push-media <targets...> [--alt <text>] [--caption <text>] [-p, --profile <name>]
```

- `<targets...>`: 1 つ以上のローカル画像パス（`media/drafts/a.jpg`, `~/Pictures/b.png` 等）、companion YAML パス（`media/<stem>.yaml`）、`<storageKey>`、または `<mediaId>`。
  - 例 1（単体アップロード＋メタ指定）: `emit push-media ~/Photos/hero.jpg --alt "表紙画像" --caption "撮影: 2026"`
  - 例 2（YAML 編集後の一括反映）: `emit push-media media/01KEY.yaml`（または `emit push-media media/*.yaml`）
  - 例 3（storageKey 指定でメタ更新）: `emit push-media 01KEY1.01KEY2.jpg --alt "新しい代替テキスト"`
- 出力には各アイテムの操作種別（`uploaded` / `deduplicated` / `metadata-updated`）、`mediaId`（frontmatter `featuredImage` 用）、`storageKey`、ローカルミラーパス（`media/<markdownRef>.<ext>`）、および反映された `alt` / `caption` を表示する。
- エラー時は Axis 8 に従い `reportActionFailure(err)` で統一出力する。

#### 2. MCP: `sync_push_media`（`src/mcp/tools/sync-media-search.ts` または `src/mcp/tools/sync-push-media.ts`、`src/mcp/server.ts` で登録）

- **ツール名**: `sync_push_media`
- **Zod スキーマ（単一 `targets` 配列に統一して AI エージェントの誤用を防止）**:
  - `targets: z.array(z.string()).min(1).describe('One or more local image paths (e.g. "media/drafts/hero.jpg"), companion YAML paths ("media/<stem>.yaml"), storageKeys, or 26-char mediaIds.')`
  - `alt: z.string().optional().describe('Alt text to set on the media record(s). Omit when pushing edits from a local media/<stem>.yaml file.')`
  - `caption: z.string().optional().describe('Caption text to set on the media record(s). Omit when pushing edits from a local media/<stem>.yaml file.')`
  - `profile: z.string().optional()`
- 戻り値は各ターゲットの `{ action: 'uploaded' | 'deduplicated' | 'metadata-updated', mediaId, storageKey, url, filePath, yamlPath, alt, caption }` と `_meta`（Axis 9 `withResolvedContext` 準拠）を返す。
