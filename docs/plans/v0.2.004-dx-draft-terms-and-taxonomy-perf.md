# v0.2.4 実装計画書: 未昇格ドラフトターム可視化・単独昇格・`# <Name>` ロケール別補完・タクソノミ同期 HTTP 最適化

- **対象バージョン**: `v0.2.4`
- **作成日**: 2026-11-27
- **ステータス**: **実装済み（2026-11-27）**
- **前提**:
  - `v0.2.0`〜`v0.2.3` の多言語ワークスペース、`drafts/<locale>/` ステージング、`byLocale` タクソノミ解決を前提とする。
  - 既存の安全性不変条件（Guard G4 / G16 / G17 / G19、Two-Layer Representation、`local_hash` 一致性）を一切弱めずに、実運用 DX と Cloudflare Workers 環境での `push` 速度を大幅に改善する。

---

## 1. 背景・目的

実運用フィードバックにより挙がった以下の 4 課題を `v0.2.4` で一括解消する：

1. **未昇格 `drafts/` タームの見落とし**: `emit status`（および `--i18n`）に `categories/drafts/`・`tags/drafts/` 内の未昇格タームが表示されず、昇格し忘れに気づきにくい。
2. **`drafts/` ターム単独昇格の不在**: 記事がすでに `[synced]` な状態や、記事執筆前にカテゴリ・タグだけ先にサーバーへ作成・昇格したい場合に `emit push --all` が「変更記事なし」でスキップしてしまう。
3. **フロントマター `# <Name>` インラインコメントのロケール不整合**: `v0.2.3` の follow-up 課題。`loadLocalTaxonomyCandidates()` がグローバル単一マップのため、日英同スラッグ・別表示名（例: `ja: ツール`, `en: Tools`）で他ロケールのラベルがコメントに出力されうる。
4. **タクソノミ無変更時の過剰な直列 HTTP 通信**: 本文・タイトルのみ修正した `emit push` でも毎回 `auditRemoteTaxonomies()`（`GET /terms/*` × 2）と `syncArticleTaxonomies()`（`POST /terms/*` × 2）が走り、1 記事あたり 4 往復のレイテンシが発生している。

### 1.1 着手前確認事項（Step 1 ゲート実測結果・2026-11-27）

- **検証内容**: `https://aroooy.net` 上で記事にタグ `t2` が付いた状態（管理画面側の変更を想定）に対し、`PUT /_emdash/api/content/posts/{id}` で `taxonomies: { tag: ["t1"] }` を送信し、`PUT` 後の `GET /terms/tag` を実測。
- **実測結果**: **YES（`PUT` の `taxonomies` がリモート関連付けを上書き変更した：`["t2"]` → `["t1"]`）**（一時リソースは削除済み）。
- **設計上の帰結（Feature 4 案A の安全分岐確定）**:
  - `PUT` が `taxonomies` を再適用するため、`noTaxonomyAudit: false`（既定・安全側）で `auditRemoteTaxonomies()` をスキップすると管理画面側のリタグを無言上書きし G16 を迂回してしまう。
  - したがって、**案A（デフォルト自動最適化）では `auditRemoteTaxonomies()`（2 GET・G16 保護）は残し、タクソノミ無変更時は `syncArticleTaxonomies()`（2 POST）のみをスキップ（4 → 2 HTTP 削減）**する。
  - 一方、**案B（`.emit/config.json` の `noTaxonomyAudit: true` または `--no-taxonomy-audit`）を有効にしたローカル完結サイト**では `auditRemoteTaxonomies()`（2 GET）もスキップされるため、タクソノミ無変更時は計 4 HTTP すべてを削減できる。

## 2. 機能別設計

### Feature 1: `emit status` への未昇格 `drafts/` ターム表示追加

- **Layer 1 (`src/sync/status.ts`)**:
  - `WorkspaceStatusResult.summary`（`src/sync/status.ts:65-83`）にオプショナルな `draftTerms` 集計を追加：
    ```ts
    draftTerms?: {
      categories: number;
      tags: number;
      total: number;
      items: Array<{
        taxonomy: 'category' | 'tag';
        locale: string;
        slug: string;
        name: string;
        filePath: string;
      }>;
    };
    ```
  - `getWorkspaceStatus()` 内で `loadLocalTaxonomyTerms(workspaceRoot)`（同一 Layer 1）から `t.isDraft === true` を抽出し、0-HTTP で集計する。
- **Layer 3 (`src/cli/commands/status.ts`, `src/mcp/tools/sync-status.ts`)**:
  - 通常表示および `--i18n` 表示のサマリー末尾に、`draftTerms.total > 0` の場合のみ以下を表示：
    `Draft terms pending push: X categories, Y tags (under drafts/) — run "emit push --terms" or "emit push <article>"`
  - MCP `sync_status` は `summary.draftTerms` をそのまま JSON に含めて返却する。

### Feature 2: `drafts/` ターム単独昇格（`emit push --terms` / MCP `sync_push({ termsOnly: true })`）および `push --all` 案内

- **Layer 1 (`src/sync/taxonomies.ts`)**:
  - 親→子トポロジカル昇格＋循環参照検出ロジックを共通ヘルパー **`promoteDraftTermsWithAncestors()`** として Layer 1（`src/sync/taxonomies.ts`）へ抽出し、Layer 2（`src/sync/push/taxonomy_plan.ts` の `promoteDraftTaxonomiesForArticle()`）と新設の **`promoteAllDraftTerms()`** の双方から共有呼び出しする（アルゴリズム二本化を防止、Layer 2 → Layer 1 方向のためレイヤリング準拠）。
  - `promoteAllDraftTerms(options)` は `loadLocalTaxonomyTerms(workspaceRoot)` から全 `isDraft === true` タームを取得し、0 件の場合は 0-HTTP で空配列を返す。
- **Layer 3 (`src/cli/commands/push.ts`, `src/mcp/tools/sync-push.ts`)**:
  - CLI `emit push` に `--terms` オプションを追加（`emit push --terms` で未昇格 `drafts/` タームのみを単独昇格。`[file]` や `--all` との同時指定時は明確なバリデーションエラーで排他制御）。
  - `emit push --all` で変更記事が 0 件だった場合、`loadLocalTaxonomyTerms()` に未昇格 `drafts/` タームが残っていれば「`No modified articles to push, but N draft term(s) are pending under drafts/. Run "emit push --terms" to promote them.`」と案内する（`[synced]` 記事を無理に再プッシュして `local_hash` や `_rev` を不要に動かさない安全設計）。
  - MCP `sync_push` に `termsOnly?: boolean` を追加し、CLI と完全対称に動作させる（新規トップレベルコマンド／MCP ツール数は増やさない）。

### Feature 3: フロントマター補完コメント（`# <Name>`）の `byLocale` 対応

- **Layer 0 (`src/utils/frontmatter.ts`)**:
  - `TaxonomyCandidates`（`src/utils/frontmatter.ts:64`）に後方互換な `byLocale?: Record<string, { slugToName?: { category?: Record<string, string>; tag?: Record<string, string>; [taxonomy: string]: Record<string, string> | undefined } }>` を追加。
  - `serializeFrontmatter()`（`src/utils/frontmatter.ts:499`）で `articleLocale = frontmatter.locale?.trim().toLowerCase()` を参照し、`candidates?.byLocale?.[articleLocale]?.slugToName?.[singularKey]` を優先、該当キーが無ければ従来のグローバル `candidates?.slugToName?.[singularKey]` へフォールバックする。
- **Layer 1 (`src/sync/taxonomies.ts`)**:
  - `loadLocalTaxonomyCandidates(workspaceRoot)`（`src/sync/taxonomies.ts:694`）で `loadLocalTaxonomyTerms(workspaceRoot)` をロケール別に走査し、`byLocale[locale].slugToName`（`slug`, `decoded`, `canonicalSlug` → `name`）を構築して返す。
- **Layer B 一貫性（`baseline-reconstruction.ts`）およびアップグレード過渡挙動**:
  - 新規書き込み 3 経路（`pull`・`push`・`reconstructBaseline()`）はいずれも `serializeMarkdown()` / `serializeFrontmatter()` と `loadLocalTaxonomyCandidates()` を共有しているため、**新規書き込み経路では**同一のロケール別 `# <Name>` 綴りが生成され偽 `[modified]` 判定は発生しない。
  - **アップグレード時の過渡状態**: すでにディスク上に旧コメント（他ロケール名）で書かれた記事がある場合、再構築ベースラインの新コメントと一時的に食い違い `emit status` で `[modified]` 表示になる可能性がある（次回 `emit push` または `emit pull` で新コメントへ正規化される）。この挙動を `CHANGELOG.md` に明記し、テストでも確認する。

### Feature 4: タクソノミ無変更時の HTTP 最適化（案A）＋ `.emit/config.json` 永続化（案B）

- **案A: ローカル無変更時の `syncArticleTaxonomies()`（2 POST）スキップ（`src/sync/push/index.ts`）**:
  - Step 1 ゲート実測結果に基づき、既存記事更新パス（`!isNewArticle`）において以下の 4 条件を**すべて**満たす場合のみ `canSkipTaxonomyPost = true` と判定する：
    1. `baseSnapshot` が存在し、`readBaselineFrontmatter(baseSnapshot)` が取得できる
    2. `!syncState?.taxonomyApplyPending`（Guard G17 保留中は必ず再送）
    3. `!options.resolveTaxonomy`（明示的競合解決指定時はスキップしない）
    4. `computeTaxonomyHash(parsed.frontmatter.taxonomies?.categories, parsed.frontmatter.taxonomies?.tags) === computeTaxonomyHash(baseFm?.taxonomies?.categories, baseFm?.taxonomies?.tags)`
  - `canSkipTaxonomyPost === true` のとき：
    - `auditRemoteTaxonomies()`（2 GET・G16 保護）は従来どおり実行し（`noTaxonomyAudit: true` 指定時のみスキップ）、**後続の `syncArticleTaxonomies()`（`POST /terms/*` × 2）をスキップ**する。
    - **`commit.ts` の `remoteTaxonomyHash` 非破壊**: スキップ時も `commitPostPush()` の `targetRemoteTaxHash` は既存の `syncState.remoteTaxonomyHash` / `calculatedTaxHash` をそのまま引き継ぎ、`null` 化しない。
- **案B: `.emit/config.json` への `noTaxonomyAudit?: boolean` 追加 + Layer 0 純関数レゾルバ（`src/utils/config.ts`, `src/cli/commands/push.ts`, `src/mcp/tools/sync-push.ts`）**:
  - `EmitConfig`（`src/utils/config.ts:28-66`）に `noTaxonomyAudit?: boolean`（デフォルト `false`）を追加。
  - Layer 0 純関数レゾルバ **`resolveNoTaxonomyAuditOption({ cliFlag, configValue })`**（`src/utils/config.ts`、`resolveLocalMediaRefsOption` 同型パターン）を新設し、優先順位「CLI/MCP 明示指定 > `.emit/config.json` > `false`」を一元化する。
