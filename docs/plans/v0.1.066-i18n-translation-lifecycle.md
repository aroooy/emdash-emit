## 1. 着手前確認事項（EmDash API 仕様との整合）

1. **翻訳作成 API (`POST /_emdash/api/content/{collection}`) と `slug` 一意性スコープ**:
   - EmDash 公式仕様（`content_create` スキーマ）により、新規作成ペイロードは `locale` と `translationOf`（元記事の 26 文字 ULID）を受け付けることを確認済み。
   - レスポンス内の翻訳グループ ID フィールド名については、`translationGroup` / `translation_group` / `translationGroupId` の揺れを防御的に吸収して読み取る設計とする。
   - **コンテンツ `slug` 一意性の `locale` スコープ（一次情報確認済み）**: EmDash 本体（`emdash-cms/emdash` `AGENTS.md`・`emdash@0.15.0` リリースノート・PR `#4524`）にて、`UNIQUE (slug, locale)` および `UNIQUE (translation_group, lower(locale))` による `(collection, locale, slug)` 単位の一意性を確認済み。Emit 側 G18 の `locale` 比較も `toLowerCase()` で大文字小文字非依存に正規化する。
2. **タクソノミーのロケール境界**:
   - EmDash 仕様では _「Term slugs are resolved in the entry's locale」_ と定義されている。元記事（例: `ja`）の `categories` / `tags` を翻訳記事（例: `en`）へ自動コピーすると別ロケール側で未登録ターム扱いになる恐れがあるため、`--translation-of` でのデフォルト引き継ぎ対象は `slug`（省略時）・`featuredImage`・`bylines` に留め、`categories` / `tags` はデフォルト空配列（明示指定時のみ設定）＋案内警告とする。

## 2. 機能別設計

### Feature 1: Frontmatter スキーマ & マッパー拡張（REQ-EMIT-I18N-2）

- **Layer 0 ([src/utils/frontmatter.ts](file:///Volumes/ext/github/emdash-emit/src/utils/frontmatter.ts))**:
  - `FrontmatterSchema` に 2 つのオプショナルフィールドを追加：
    - `translationOf: z.string().length(26).optional()`（新規翻訳作成時の元記事 ULID）
    - `translationGroup: z.string().length(26).optional()`（サーバー確定済みの共有翻訳グループ ULID）
  - `serializeMarkdown()` は両フィールドが存在する場合のみ出力する（単一言語記事の出力バイト列・`local_hash` には一切変化を与えない 100% 後方互換）。
- **Layer 0 ([src/client/mapper.ts](file:///Volumes/ext/github/emdash-emit/src/client/mapper.ts))**:
  - `ContentUpdatePayload` にオプショナルな `translationOf?: string` を追加し、`localToApiPayload()`（`create` / `update` 共用）では `options?.includeTranslationOf`（または呼び出し元の `src/sync/push/index.ts` の `mode === 'create'` 経路でのみ付与）によって **`POST` 新規作成時のみ `translationOf` を送信し、`PUT` 更新時には送信しない** ことを構造的に担保する。
  - `apiResponseToLocal()` で `raw.translationGroup ?? raw.translation_group ?? raw.translationGroupId` を `frontmatter.translationGroup` へマッピングする。

### Feature 2: Guard G18 (`DUPLICATE_SLUG_CONFLICT`) の `(collection, locale, slug)` 一意化

- **Layer 0 ([src/db/cache.ts](file:///Volumes/ext/github/emdash-emit/src/db/cache.ts))**:
  - 既存の `getSyncStateBySlug(slug)` / `getEntryBySlug(slug, collection)` は 1 件のみ返す設計のため、同一 `slug` を複数言語で共有すると片方の言語しか検知できない。これを補う **`getSyncStatesBySlug(slug): SyncState[]`** および **`getEntriesBySlug(slug, collection): CacheEntry[]`** を追加する（DB スキーマ変更・マイグレーション不要）。
  - なお、`sync_state` テーブルには `collection` 列が無いため、`getSyncStatesBySlug()` の結果に対しては `localFilePath` の先頭コレクション名（例: `posts/...`）または対応する `base_snapshots` で `collection` 境界をフィルタする。
- **Layer 1 ([src/sync/guards.ts](file:///Volumes/ext/github/emdash-emit/src/sync/guards.ts))**:
  - `GUARD_REGISTRY` および `REMEDIATION_MAP` の G18（`DUPLICATE_SLUG_CONFLICT`）説明文言を「同一コレクション・同一ロケール内での重複スラッグ検証」へ更新する。
- **Layer 2 ([src/sync/new.ts](file:///Volumes/ext/github/emdash-emit/src/sync/new.ts))**:
  - `findLocalDuplicateSlug(workspaceRoot, collection, slug, cache, locale?)` を拡張し、`getSyncStatesBySlug` / `getEntriesBySlug` を用いて重複判定キーを **`(collection, locale, slug)`** 単位にする。
  - 同一 `slug` がワークスペースまたは `cache.db` に存在していても、既存記事の `locale` が作成対象の `locale` と異なる場合は重複エラーにせず通過させる（例: `ja` と `en` で同一 `slug` を使用可能）。
  - 既存記事の `locale` はワークスペース実ファイル（`parseMarkdownLenient()`）または `base_snapshots.frontmatter_yaml` から参照し、取得不能な場合のみ安全側（重複扱い）に倒す。同一 `(collection, locale, slug)` の場合は従来どおり Guard **G18 (`DUPLICATE_SLUG_CONFLICT`)** で拒否する。

### Feature 3: ローカル翻訳スキャフォールド & Push 連携（REQ-EMIT-I18N-1, 5）

- **Layer 2 ([src/sync/new.ts](file:///Volumes/ext/github/emdash-emit/src/sync/new.ts))**:
  - `CreateScaffoldOptions` に `translationOf?: string`（元記事のファイルパスまたは 26 文字 ULID）を追加。
  - `translationOf` 指定時の挙動：
    1. 元記事をワークスペース（または `cache.db`）から解決し、`sourceId`（26 文字 ULID）・`sourceLocale`・`sourceSlug`・`sourceFeaturedImage`・`sourceBylines` を取得。**元記事がワークスペースにも `cache.db` にも見つからない場合は明示エラーとし、`emit pull <id>` で先に元記事を取得するよう案内する。**
    2. 作成対象 `locale` が `sourceLocale` と同一の場合はエラーで拒否（同言語の重複翻訳を防止）。
    3. `slug` が未指定の場合は `sourceSlug` を自動継承。`featuredImage` / `bylines` も未指定時は元記事から継承。`categories` / `tags` はロケール境界保護のためデフォルト空とし、`warnings` に案内を出力。
    4. 新規ファイルは常に `status: draft` として `posts/draft/` に生成（公開には既存の `--allow-publish` が必須 — REQ-5 準拠）。
    5. フロントマターに `translationOf: <sourceId>`（元記事に `translationGroup` があれば参考情報として `translationGroup` も併記可能）を記録。
- **Layer 2 ([src/sync/push/index.ts](file:///Volumes/ext/github/emdash-emit/src/sync/push/index.ts), [src/sync/push/commit.ts](file:///Volumes/ext/github/emdash-emit/src/sync/push/commit.ts))**:
  - `mode === 'create'` の `POST /_emdash/api/content/{collection}` 送信時、`parsed.frontmatter.translationOf` が存在すればペイロードに含める。
  - 作成レスポンスに `translationGroup`（または `translation_group` / `translationGroupId`）が含まれる場合、`commitPostPush` で `savedFrontmatter.translationGroup` を記録し、作成専用入力である `translationOf` をクリアしてローカルへ書き戻す（以降の編集・同期をクリーンに保つ）。
- **Layer 3 ([src/cli/commands/new.ts](file:///Volumes/ext/github/emdash-emit/src/cli/commands/new.ts), [src/mcp/tools/sync-new.ts](file:///Volumes/ext/github/emdash-emit/src/mcp/tools/sync-new.ts))**:
  - CLI: `emit new [slug]` に `--translation-of <fileOrId>` を追加（`--translation-of` 指定時は `slug` 省略可。未指定かつ `slug` 省略時は従来どおりエラー）。
  - MCP: `sync_new` に `translationOf?: string` を追加（`slug` は `translationOf` 指定時に省略可）。

## 6. 今後の多言語ロードマップ課題（Phase 2 以降のスコープ）

本版（Phase 1）では対象外とし、後続フェーズで検討する多言語関連の設計論点を以下に記録する：

1. **多言語タクソノミー同期（`taxonomy_term_translations`）**: `categories/*.yaml` / `tags/*.yaml` が現状単一ロケール前提のため、異言語で同一スラッグのカテゴリ・タグを運用するケースへの対応。
2. **多言語バイライン（`byline_translations`）**: ロケール別執筆者プロフィールの同期対応。
3. **`emit pull` のウィンドウ上限と剪定（`postsSyncLimit`）**: 言語数倍に増えるレコードに対する `--locale` フィルタやウィンドウ調整の検討。
4. **スナップショット & 検索の拡張**: `emit status --i18n`（Phase 2、EmDash 公式 `GET /_emdash/api/content/{collection}/{id}/translations` 活用可）とあわせた `snapshot_articles.translation_group` カラム追加（Schema マイグレーション）および `article-search --locale` フィルタ。
