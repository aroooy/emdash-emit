# v0.2.2 実装計画書: 既存カテゴリ・タグの更新サポート（`emit update-term` / `sync_update_term`）

- **対象バージョン**: `v0.2.2`
- **作成日**: 2026-11-27
- **ステータス**: **実装済み（2026-11-27）**
- **前提**:
  - `v0.2.0` のロケール別タクソノミー構造（`categories/<locale>/*.yaml`, `tags/<locale>/*.yaml`）および `v0.2.1` の `drafts/` ステージングを前提とする。
  - 既存の `emit push` パイプラインを複雑化・脆弱化させないため、記事の `push` とは独立して事前に呼び出す**即時リモート反映型**（`emit push-media <target> --alt ...` と同一モデル）を採用する。

---

## 1. 背景・目的と一次情報ゲート

### 1.1 背景

- `v0.2.1` で完全オフラインでのカテゴリ・タグ新設（`emit new-term` / `sync_new_term`）は可能になったが、既存タームの表示名（`name` / `label`）、`slug`、親カテゴリ（`parentId` / 親解除）、`description` を Emit から更新する手段が無かった。
- 従来の `emit push` は変更された記事を起点に動作するため、記事を書かずにカテゴリ／タグだけを整理したいユースケースや、`push` 前にターム定義を整えておきたいユースケースに対応するため、明示的な更新コマンド／MCP ツールを追加する。

### 1.2 基本設計方針（即時リモート反映型）

1. **記事 `push` の前に独立実行する**:
   - `emit update-term`（MCP: `sync_update_term`）は実行時にリモート API へ直接更新リクエストを送り、成功後にローカルの `categories/` / `tags/` YAML を最新化する。
   - そのため、後続の `emit push`（冒頭の `pullTaxonomies()` およびローカル YAML 読み込み）は**更新済みの最新タクソノミー**をそのまま正本として利用できる。
2. **`locale` は「更新する値」ではなく「対象を特定するセレクタ」**:
   - 同じ `slug` を共有する複数翻訳タームが存在する場合に、どの言語版を更新するかを絞り込むために使用する（既存タームの言語自体を書き換えることはしない）。
3. **未昇格 `drafts/` タームへの配慮**:
   - まだリモートに存在しない `drafts/<locale>/*.yaml` に対して呼ばれた場合は、リモート API を叩かずにローカル draft YAML を直接更新し、`emit push` 時の自動作成に反映できるようにする。

### 1.3 着手前確認事項（Step 1 一次情報ゲート）

- **確認済み（EmDash 公式 MCP `taxonomy_update_term` スキーマより）**:
  - 識別キー: `taxonomy`, `termSlug`（+ 任意で翻訳特定用 `locale`）
  - 更新可能フィールド: `label?: string`, `slug?: string`, `parentId?: string | null`（`null` で親から切り離し）, `description?: string`
  - サーバー側制約: `slug` 重複禁止、親の循環参照および 100 階層超の拒否
- **実サーバー（`https://aroooy.net`）での実測結果（2026-11-27 記録・Step 1 Gate 完了）**:
  1. **更新 REST エンドポイント & メソッド**:
     - `PATCH /_emdash/api/taxonomies/{taxonomy}/terms/{termSlug}` → `404`
     - **`PUT /_emdash/api/taxonomies/{taxonomy}/terms/{termSlug}`** → **`200 OK`**（任意でクエリ `?locale=<locale>` を付与）。
     - レスポンス構造: `{"success":true,"data":{"term":{"id":...,"name":...,"slug":...,"label":...,"parentId":...,"description":...,"locale":...,"translationGroup":...}}}`（`unwrapEnvelope()` で `data.term` を抽出可能）。
  2. **`slug` 変更時のサーバー側カスケード可否**:
     - **自動追従する（YES）**。D1 側で記事とタームが `termId` で結合されているため、`slug` を `emit-cascade-test` → `emit-cascade-test-v2` へ変更後、`GET /_emdash/api/content/posts/{id}/terms/tag` は即座に新 `slug`（`emit-cascade-test-v2`）を返却した。
     - したがって、ローカル記事に旧 `slug` が残っている場合は、`emit pull`（既存の respell 機構）でローカル記事を新 `slug` に揃えられるため、警告文は「未編集記事は `emit pull` で新 `slug` へ同期可能（ローカルに未 push 編集がある場合はフロントマターを新 `slug` へ更新してから `emit push`）」と案内する。
  3. **`GET terms` レスポンスにおける `description` の有無**:
     - **含まれる（YES）**。`GET /_emdash/api/taxonomies/{taxonomy}/terms` の返却アイテムに `"description"` が含まれることを実測確認済み。
     - したがって、同期済みローカル YAML（`serializeTaxonomyYaml()` / `loadLocalTaxonomyTerms()`）にも `description` を永続化する（未設定時は省略）。

## 2. 機能別設計

### Layer 0: エンドポイント定義（`src/client/endpoints.ts`）

- Step 1 Gate で確定したパスに基づき `taxonomyTermEndpoint(origin, taxonomy, termKey, locale?)` を追加する。

### Layer 1: タクソノミー更新・昇格連結・YAML 同期（`src/sync/taxonomies.ts` + `src/sync/push/taxonomy_plan.ts`）

1. **`description` フィールドの扱いと `drafts/` 昇格時の流出防止**:
   - `TaxonomyTerm`、`LocalTaxonomyItem`、`serializeTaxonomyYaml()`（`src/sync/taxonomies.ts:118` のインライン引数型）および `loadLocalTaxonomyTerms()`（`src/sync/taxonomies.ts:515`）に任意の `description?: string` を対応させる（同期済み YAML への永続化有無は Step 1 Gate #3 の結果に従う）。
   - **重要（`v0.2.1` 結合修正）**: `drafts/` タームに `update-term --description`（または将来の拡張）で設定された `description` が `emit push` 昇格時に黙失しないよう、`createRemoteTaxonomyTerm()`（`src/sync/taxonomies.ts`）および `promoteTermWithAncestors()` 内の呼び出し（`src/sync/push/taxonomy_plan.ts:147-158`）の `POST` ペイロードへ `description` を追加する。
2. **ターゲット解決 (`resolveLocalTermTarget`)**:
   - `<target>` として **26 文字 ULID**、**YAML ファイルパス**（例: `categories/ja/01ABC...-news.yaml`）、または **`slug`**（デコード済み CJK / パーセントエンコード済み両対応、任意で `--locale` 絞り込み）を受け付ける。
   - `loadLocalTaxonomyTerms()` の結果から対象を特定し、同一 `slug` が複数ロケールに存在し `--locale` 未指定で一意に決まらない場合は曖昧エラーとして中断し、`--locale` または ULID 指定を案内する。
3. **事前バリデーション & Fail-Fast 重複チェック**:
   - 更新フィールド（`name`, `slug`, `parent` / `clearParent`, `description`）が 1 つも指定されていない場合は即エラーで中断。
   - `tag` に対して `--parent` / `--clear-parent` が指定された場合は拒否する。
   - `--parent <slugOrId>` は `taxonomy-key.ts`（`normalizeTaxonomyKey` / `aliasesOf`）の正規化を再利用してローカルカテゴリから 26 文字 ULID へ解決する（`--clear-parent` / `parentId: null` 指定時は `null` を送信）。
   - `slug` リネーム時は、リモート送信前に同一 `(taxonomy, locale, slug)` のローカル重複を `normalizeTaxonomyKey` / `aliasesOf` で事前検査し、衝突があれば **`DUPLICATE_TERM_SLUG`** で fail-fast する（サーバー 409 待ちにしない）。
4. **リモート更新 (`updateTaxonomyTerm`)**:
   - 対象が `isDraft === true`（`drafts/` 配下）の場合は、ローカル draft YAML の該当フィールドを更新して返却（オフラインのまま完結）。
   - リモートタームの場合は API へ更新リクエストを送信。HTTP エラー時は **`TAXONOMY_UPDATE_FAILED`** をスローしてローカルファイルを破壊しない。
   - 更新成功後は `pullTaxonomies()`（部分失敗保護付き）を実行し、YAML ファイル名変更（`label` 変更時）や旧ファイルの prune を含めてローカルミラーを最新化する。
5. **`slug` 変更時のローカル記事参照チェック（警告のみ・自動書き換えなし）**:
   - `slug` が変更された場合、`posts/` 配下（`draft/`, `published/`, `conflicts/` すべてを含む）を `fs` + `parseMarkdownLenient()`（Layer 0 / Axis 7 準拠、Layer 1 → Layer 2 逆依存を回避）で走査する。
   - `normalizeTaxonomyKey()` / `aliasesOf()`（G4 と同一正規化軸）を用いて decoded CJK / percent-encoded 両形で旧 `slug` 参照を照合し、該当記事パスを `warnings` として返却する（記事ファイルの自動書き換えは行わず、意図しない `local_hash` 攪乱を回避する。Layer B の綴り修復責務は `pull` 側既存の respell 機構へ委ねる）。

### Layer 1: エラーコード登録（`src/sync/guards.ts`）

- `OPERATIONAL_ERROR_CODES` および `REMEDIATION_MAP` に `TAXONOMY_UPDATE_FAILED` を登録する（`TAXONOMY_CREATE_FAILED` と同系列）。

### Layer 3: CLI & MCP ツール（対称設計）

- **CLI (`src/cli/commands/update-term.ts`, `src/bin/emit.ts`)**:
  - `emit update-term <taxonomy> <target>`
  - オプション: `-n, --name <label>`, `--slug <slug>`, `--parent <slugOrId>`, `--clear-parent`, `-d, --description <text>`, `-l, --locale <locale>`, `-p, --profile <name>`
  - Axis 8 準拠: エラーハンドリングは必ず `reportActionFailure()` 経由。
  - 更新内容および `slug` 変更時の旧参照記事警告（Step 1 Gate #2 に基づくリメディエーション付き）を表示。
- **MCP (`src/mcp/tools/sync-update-term.ts`, `src/mcp/server.ts`)**:
  - `sync_update_term`: `{ taxonomy, target, name?, slug?, parent?, clearParent?, description?, locale?, profile? }`
  - Axis 9 準拠: `withResolvedContext()` でラップし、`_meta` と `warnings` を含めて返却。
