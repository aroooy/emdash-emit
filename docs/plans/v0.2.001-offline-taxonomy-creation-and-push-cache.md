# v0.2.1 実装計画書: 完全オフラインでのカテゴリ・タグ新設（`drafts/` ステージング）および `pushAll` タクソノミー同期・キャッシュ最適化

- **対象バージョン**: `v0.2.1`
- **作成日**: 2026-11-27
- **ステータス**: **Rev.2（第三者レビュー 7 点反映済み・承認待ち）**
- **前提**:
  - `v0.2.0` のロケール別タクソノミー構造（`categories/<locale>/*.yaml`, `tags/<locale>/*.yaml`）を前提とする。
  - Guard **G4（`INVALID_TAXONOMY_ERROR`）** によるタイポ・ハルシネーション防止を一切弱めずに、完全オフライン環境での新規カテゴリ／タグ作成と `emit push` 時の自動リモート作成・昇格を実現する。

---

## 1. 背景・目的と一次情報ゲート

### 1.1 背景

1. **オフラインでのタクソノミー新設不可**:
   - 現状の Emit は `categories/`・`tags/` の読み取り専用ミラーのみを提供しており、新設したいカテゴリやタグがある場合はオンライン状態で管理画面または EmDash MCP を別途操作する必要があった。
2. **`pushAll`（`emit push --all`）のタクソノミー同期＆I/O 重複**:
   - `pushAll()`（`src/sync/orchestrator.ts`）は冒頭で `pullTaxonomies()` を呼ばず、さらにループ内の各 `pushArticle()` ごとに `loadLocalTaxonomyMaps()` と `loadLocalTaxonomyCandidates()` を毎回ディスクから読み込み直していた（$N$ 記事で全タクソノミー YAML を $2N$ 回同期パース）。
   - `runPreflightChecks()`（`src/sync/preflight.ts`）の存在判定も `allowed.includes(term)` の $O(N)$ 線形探索となっていた。

### 1.2 基本設計方針（Local-First `drafts/` ステージング）

`media/drafts/`（オフライン画像ステージング → `emit push` 時の自動アップロード＆昇格）と同一の設計パターンをタクソノミーへ適用する。

```text
workspace/
├── categories/
│   ├── ja/*.yaml                 # サーバー同期済み（正規 ULID）
│   ├── en/*.yaml
│   └── drafts/                   # オフライン新設ステージング（pull prune 対象外）
│       ├── ja/<provisionalId>-<name>.yaml
│       └── en/<provisionalId>-<name>.yaml
└── tags/
    ├── ja/*.yaml
    ├── en/*.yaml
    └── drafts/
        ├── ja/<provisionalId>-<name>.yaml
        └── en/<provisionalId>-<name>.yaml
```

- **記事フロントマターからの無条件自動作成は行わない**: タイポを本番へ増殖させないため、オフラインで `emit new-term`（または `sync_new_term`）により明示的に `drafts/` へステージングされたタームのみを有効候補として認め、未登録の文字列は従来どおり Guard **G4** で拒否する。

### 1.3 着手前確認事項（一次情報ゲート）

実装着手前（Step 1）に、EmDash 1.4+ 実サーバーまたは EmDash ソースにて **`POST /_emdash/api/taxonomies/{taxonomy}/terms`** の以下を確認し、本節に記録する：
1. リクエストボディの正確なフィールド名（`label` vs `name`、`slug`、`parentId` vs `parent`、`locale`、`translationOf` / `translationGroup` の受け付け有無）。
2. レスポンスエンベロープからサーバー採番 `id`（および `slug` / `translationGroup`）を取り出す構造、および**サーバーが返却する `slug` がリクエストと一致すること**（サーバー側で予期せぬ正規化・サニタイズが行われ `slug` が相違する場合は、ローカル記事の参照や次回 G4 判定が壊れるため **`TAXONOMY_SLUG_MISMATCH` で安全中断し、昇格を行わない**）。
3. 同一 `(taxonomy, locale, slug)` が既にリモートに存在する場合のステータスコード（HTTP 409 か 200 か）と、競合時の安全な回復挙動（既存リモートターム ID を再取得して昇格するかエラー中断するか）。

## 2. 機能別設計

### Feature 1: `pushAll` 初手タクソノミー同期・1 回読み込みキャッシュ・`Set` 化

- **Layer 1 (`src/sync/preflight.ts`)**:
  - `runPreflightChecks()` の G4 存在判定を `const allowedSet = new Set(allowed)` に変更し、判定コストを $O(1)$ 化。
- **Layer 2 (`src/sync/push/types.ts`, `src/sync/push/index.ts`, `src/sync/orchestrator.ts`)**:
  - `PushOptions` に `taxonomyMaps?: ReturnType<typeof loadLocalTaxonomyMaps>` を追加。
  - `pushArticle()` は `options.taxonomyMaps ?? loadLocalTaxonomyMaps(options.workspaceRoot)` を使用し、事前注入時はディスク再読み込みをスキップする。
  - `pushAll()` 冒頭（`toPush.length > 0` の場合）に以下を実施：
    1. `pullTaxonomies()` を 1 回だけ実行してローカル定義を最新化する。`pullTaxonomies()` 既存の**部分失敗保護契約**（`categories` / `tags` を独立 `catch(() => null)` し、失敗した側のみ書き込み・prune をスキップして既存定義を温存、`drafts/` は常時保護）がそのまま成立し、全失敗／片側失敗時も `warnings` に記録して既存ローカル定義で安全に続行する。
    2. `loadLocalTaxonomyMaps()` と `loadLocalTaxonomyCandidates()` を **1 回だけ** メモリに読み込み、ループ内の全 `pushArticle()` へ注入する。

### Feature 2: 完全オフラインでのカテゴリ・タグ新設（Layer 1 + Layer 3）

- **Layer 1 (`src/sync/taxonomies.ts`)**:
  - `LocalTaxonomyItem` に `isDraft?: boolean; filePath?: string; translationOf?: string;` を追加。
  - **`writeAndPruneTaxonomyDir()` の `drafts/` 保護**:
    - `entry.name === 'drafts'` を予約ディレクトリとしてスキップし、`pullTaxonomies()` 実行時にオフライン下書きタームを絶対に削除しない。
  - **`readTaxonomyDir()` の `drafts/` 読み込み**:
    - 既存の `<dir>/<locale>/*.yaml`（および読み取り専用互換の直下 `*.yaml`）に加え、`<dir>/drafts/<locale>/*.yaml` も読み込み、`isDraft: true` と `filePath` を付与して返す。
    - これにより `loadLocalTaxonomyMaps()`・`loadLocalTaxonomyCandidates()`・`loadLocalTaxonomyTerms()`（Auto-Map）・G4 Preflight が自動的に下書きタームを認識する。
  - **`createLocalDraftTerm(options)`（0-HTTP）**:
    - 引数: `{ workspaceRoot, taxonomy: 'category' | 'tag', slug, name?, locale, parent?, translationOf? }`
    - 仮 ULID（`ulid()`）を採番し、同一 `(taxonomy, locale, slug)` の重複判定は `taxonomies.ts` 既存の **`canonicalSlugOf` / `aliasesOf` / `normalizeTaxonomyKey`** を再利用して G4 と同一の判定軸で比較し、重複時はエラー拒否（`DUPLICATE_TERM_SLUG`）。
    - `parent` 指定時はローカル定義（`drafts/` 含む）から親ターム ID を解決（未発見時はエラー）。
    - `categories/drafts/<locale>/<provisionalId>-<sanitizedLabel>.yaml`（または `tags/drafts/<locale>/...`）へ書き出し、結果（`id`, `slug`, `filePath`, `locale`）を返す。
- **Layer 3 (CLI & MCP)**:
  - **CLI**（独立ファイル `src/cli/commands/new-term.ts` を新設し `src/bin/emit.ts` で登録 — Axis 8 の明確性を維持）:
    - `emit new-term <taxonomy> <slug> [--name <label>] [-l, --locale <locale>] [--parent <slugOrId>] [--translation-of <termId>] [-p, --profile <name>]`
    - すべてのエラーを `reportActionFailure()` 経由で出力（Axis 8 準拠）。
  - **MCP**（独立ファイル `src/mcp/tools/sync-new-term.ts` を新設し `src/mcp/server.ts` で登録）:
    - `sync_new_term` ツールを登録し、`withResolvedContext()` 経由で実行（Axis 9 準拠）。

### Feature 3: `emit push` / `emit push --all` 時の下書きターム自動作成＆プロモーション

- **Layer 1 (`src/sync/taxonomies.ts`)**:
  - `createRemoteTaxonomyTerm(options)`: `POST /_emdash/api/taxonomies/{taxonomy}/terms` を実行し、サーバー採番の正規 `TaxonomyTerm` を返す。
  - `promoteLocalDraftTerm(params)`: `drafts/<locale>/<provisionalId>-...yaml` の内容とサーバー応答から正規パス `<locale>/<serverId>-<sanitizedLabel>.yaml` を書き出し、仮ファイルを削除する。
- **Layer 2 (`src/sync/push/taxonomy_plan.ts`, `src/sync/push/index.ts`)**:
  - `promoteDraftTaxonomiesForArticle()` を新設し、`pushArticle()` の記事 `POST`/`PUT` 前段で実行する：
    1. 記事の `frontmatter.taxonomies.{categories,tags}` が参照するタームのうち、`isDraft === true` なものを抽出。
    2. 階層カテゴリで `parentId` が別の `drafts/` タームを指している場合、**親 → 子の依存順（トポロジカル順）** で順次 `createRemoteTaxonomyTerm()` を実行し、子の `parentId` を親の正規 ULID に差し替えて作成する（循環参照はガード）。
    3. 各タームの作成成功後、返却された `slug` が期待正規スラッグと一致することを検証（不一致時は `TAXONOMY_SLUG_MISMATCH` で中断・未昇格）。一致確認後に `promoteLocalDraftTerm()` で正規パスへ昇格し、メモリ上の `taxonomyMaps`（`slugToId` / `idToSlug`）と `candidates`、および記事内の仮 ULID 参照を即時更新する。
    4. `pushAll()` で共有されている `taxonomyMaps` をインプレース更新することで、後続記事が同じ新設タームを参照しても二重 POST しない。また別プロセス（次回の `emit push`）では既に正規パスへ昇格済みの YAML が `isDraft: false` として読み込まれるため二重 POST は発生しない。
    5. **`sync_state.remote_taxonomy_hash` との整合性**: プロモーションと `parsed.frontmatter.taxonomies` の正規化が記事 `POST`/`PUT` および `push/commit.ts` より前に完了するため、`push/commit.ts` の `computeTaxonomyHash()` が昇格後の正規ターム集合から `remote_taxonomy_hash` を自動計算・保存する。これにより、次回 `emit status` / `emit pull` で誤ったタクソノミー変更検知（drift）は発生しない。
    6. 作成失敗時は仮ファイルを `drafts/` に残したまま `ApiError`（`TAXONOMY_CREATE_FAILED`）で安全中断する（再実行で冪等に復旧可能）。
