## 1. 着手前確認事項（EmDash 1.5 / 1.6 レスポンス形状）

1. **REQ-2 (`GET/POST /_emdash/api/content/{collection}/{id}/lock`)**:
   - EmDash 1.5.0+ の `room?: boolean` フィールド（トップレベルまたは `data.room` の双方に対応できるよう防御的に読み取る）。EmDash 1.4 以前では `undefined` のため後方互換 100%。
   - **実サーバー確認事項**: `room: true` 検知後に呼び出し元が `DELETE /lock` を送った際、リース解除のみに留まりブラウザ側の Co-editing ルーム自体を強制終了・破壊しないこと（もし破壊する仕様の場合は `GET /lock` 先行確認へ切り替える）。
2. **REQ-4 (`GET /_emdash/api/media/{id}`)**:
   - EmDash 1.6.0+ の `usedIn` 配列（`item.usedIn` または `data.usedIn` の双方に対応できるよう防御的に抽出）。要素が `{ id, title, slug, collection, status }` 等のオブジェクトでも文字列でも人間可読に整形できるよう設計する。

## 2. 機能別設計

### Feature 1 (REQ-2): Co-editing ルームのアクティブ検知・衝突警告（新設 Guard G23）

- **Layer 0 ([src/client/lock.ts](file:///Volumes/ext/github/emdash-emit/src/client/lock.ts))**:
  - `LockResponse` に `room?: boolean` を追加。
  - `LockClientOptions` に `allowActiveCoediting?: boolean` を追加。
  - `acquireLock()` でレスポンスを解析した際、`room === true && !options.allowActiveCoediting` であれば、`EntryLockError`（code: `'ACTIVE_COEDITING_SESSION'`）を送出する。
    - もし当該 `POST .../lock` で呼び出し元がロックを取得してしまっていた場合（`json.heldByCaller === true`）は、例外送出前にベストエフォートで `releaseLock()` を呼んでロックを残さない。
  - これにより、`acquireLock()` を通る全書き込み経路（`emit push` / `emit publish` / `emit discard-draft` および対応する MCP ツール）が一括で Co-editing 衝突から保護される。
- **Layer 1 ([src/sync/guards.ts](file:///Volumes/ext/github/emdash-emit/src/sync/guards.ts))**:
  - `GUARD_REGISTRY` に **G23 (`ACTIVE_COEDITING_SESSION`)** を追加（`stage: 'push'` — `GuardMeta.stage` は単一値のため代表ステージを `'push'` とし、`description` にて `push / publish / discard-draft` 全 3 経路を保護する旨を明記、`severity: 'error'`, `source: 'src/client/lock.ts'`）。
  - `REMEDIATION_MAP` に `ACTIVE_COEDITING_SESSION` の案内（ブラウザエディタを閉じるか `--force` で上書き実行する旨。あわせて `push` / `discard-draft` では `--force` が既存の競合上書き・退避オプションも兼ねる点に留意する旨を注記）を追加。
- **Layer 2 / Layer 3（バイパス配線）**:
  - `pushArticle`（`src/sync/push/index.ts`）・`discardDraftArticle`（`src/sync/orchestrator.ts`）では既存の `options.force` を `acquireLock(..., { allowActiveCoediting: Boolean(options.force) })` に接続する。
  - `publishArticle`（`src/sync/orchestrator.ts`）・`emit publish`（`src/cli/commands/publish.ts`）・MCP `sync_publish`（`src/mcp/tools/sync-publish.ts`）にも任意オプション `force?: boolean`（`-f, --force`: アクティブ Co-editing 警告のバイパス用）を追加する（未プッシュ変更や G22 は従来どおり保護を維持）。

### Feature 2 (REQ-4): メディア使用状況（`usedIn`）連動による Guard G20 強化

- **Layer 0 ([src/client/media.ts](file:///Volumes/ext/github/emdash-emit/src/client/media.ts))**:
  - `RemoteMediaUsageRef` 型（`{ id?: string; collection?: string; title?: string; slug?: string; status?: string }`）と、`RemoteMediaDetail.usedIn?: RemoteMediaUsageRef[]` を追加。
  - `fetchRemoteMediaDetail()` で `GET /_emdash/api/media/{id}` のレスポンスから `usedIn` を抽出して返す（**追加 HTTP リクエスト 0**）。
- **Layer 2 ([src/sync/media/delete_media.ts](file:///Volumes/ext/github/emdash-emit/src/sync/media/delete_media.ts))**:
  - 既存のローカルワークスペース記事スキャン（Guard G20）に加えて、`fetchRemoteMediaDetail()` が `usedIn` 配列を返し、要素が 1 件以上ある場合も **同一の Guard G20 (`MEDIA_IN_USE_PROTECTION`)**（バイパスなし・既存原則を維持）で削除を拒否し、リモート使用箇所（例: `remote:posts:"Title" (<ULID>)`）を `referencedBy` に含めて報告する。
  - サーバーが `usedIn` を返した場合（EmDash 1.6+）はリモート参照検証済みであることを結果に反映し、未返却の場合（EmDash 1.4 以前や `--dry-run` のオフラインモード）は従来どおり `[LOCAL_REFERENCE_SCAN_ONLY]` 警告を維持する。

### Feature 3 (`v0.1.64` レビュー残件): 公開後再 `GET` 失敗時の回帰テスト追加

- [tests/publish_command.test.ts](file:///Volumes/ext/github/emdash-emit/tests/publish_command.test.ts) に、`publishArticle` で `POST .../publish` 成功後の再 `GET` が 503 を返した場合に以下 3 点を検証するテストケースを追加：
  1. `ApiError`（code: `PUBLISH_FAILED`）が送出されること
  2. `suggestion` に `emit pull <id>` が含まれること
  3. `DELETE .../lock` によるロック解放が確実に呼ばれること
