# v0.2.0 実装計画書: Multi-Language First ワークスペース刷新（言語別フォルダ構造・多言語タクソノミー Auto-Map・翻訳カバレッジ）

- **対象バージョン**: `v0.2.0`（破壊的変更を伴うマイナーバージョンアップ）
- **作成日**: 2026-11-27
- **ステータス**: **実装済み（2026-11-27）**
- **方針**: 多言語対応は EmDash のコア機能であるため、旧フラット構造（`<collection>/{draft,published}/`）との後方互換分岐は持たず、**`<collection>/<locale>/{draft,published}/`** を唯一の正規構造へ統一する（`.emit/config.json` に切替設定を増やさず、全層を単一ルールでシンプルに保つ）。
- **スコープ外（見送り）**: REQ-EMIT-I18N-5（`emit push --publish` / `emit new --status published`）は「下書きの誤本番公開防止」の安全原則および既存 `--allow-publish` との意味混同を避けるため本版では導入しない。

---

## 1. 破壊的変更（Breaking Changes）とアップグレード導線

1. **正規ワークスペース構造の刷新**:
   - **旧 (`v0.1.x`)**: `posts/draft/<file>.md`, `posts/published/<file>.md`（相対メディア参照: `../../media/<key>`）
   - **新 (`v0.2.0`)**: **`posts/<locale>/draft/<file>.md`**, **`posts/<locale>/published/<file>.md`**（例: `posts/ja/published/...`, `posts/en/draft/...`、相対メディア参照: **`../../../media/<key>`**）
   - **据え置き**: `posts/conflicts/` はコレクション直下に維持する（`isQuarantinedRelativePath` の `segments[1] === 'conflicts'` 契約を保護し、退避ファイルの集約性を維持）。
2. **既存環境（`v0.1.x`）からの安全なアップグレード導線**:
   - `emit doctor`（`src/sync/doctor.ts`）に **旧フラットレイアウト検知チェック（`legacy-flat-layout`）** を追加し、`<collection>/draft/*.md` または `<collection>/published/*.md` にファイルが残存している場合は警告を表示して移行手順（「未プッシュ変更が無いことを確認のうえ旧ファイルを退避・削除し、`emit pull` で新構造へ再同期」）を案内する。
   - `CHANGELOG.md` に `BREAKING CHANGES` とアップグレード手順を明記する（**ウィンドウ外記事は `emit pull <id>` で個別再同期が必要な点**、および **アップグレード後〜再同期完了までの過渡状態では `emit status` が旧パス由来の記事を未検出／missing 扱いする点** を明示）。
3. **着手前確認事項（Features 2 / 3 の前提）**:
   - EmDash `GET /_emdash/api/taxonomies/{taxonomy}/terms`（`locale` クエリ省略時に全ロケール返却）のレスポンスに `locale` および `translationGroup`（または `translation_group` / `translationGroupId`）が含まれることを実サーバーまたは EmDash ソースで確認する（未返却の旧サーバーでは `locale` / `translationGroup` を省略して従来互換を維持し、Auto-Map は同一 `slug` フォールバックへ安全に縮退する）。

## 2. 機能別設計

### Feature 1 (REQ-3 / Breaking): `<collection>/<locale>/{draft,published}/` 構造への統一

- **Layer 0 ([src/utils/naming.ts](file:///Volumes/ext/github/emdash-emit/src/utils/naming.ts))**:
  - `computeArticleRelativePath(collection, status, id, titleOrSlug, dateInput, locale)` の **`locale: string` を必須パラメータ**（デフォルト `'ja'` を設けない）とし、`const safeLocale = locale.trim().toLowerCase()`（空文字時はエラーまたは明示正規化）を組み込んだ `${collection}/${safeLocale}/${status}/${prefix}${id}-${safeTitle}.md` を返す。これにより `locale` の渡し忘れを TypeScript コンパイラが静的に全件検知し、`en` 記事の `posts/ja/` 誤配置を構造的に防ぐ。
- **Layer 2 ([src/sync/workspace/articles.ts](file:///Volumes/ext/github/emdash-emit/src/sync/workspace/articles.ts), [src/sync/workspace/index.ts](file:///Volumes/ext/github/emdash-emit/src/sync/workspace/index.ts))**:
  - `WorkspaceArticleEntry` に `locale?: string` を追加。
  - `iterWorkspaceArticles()` は `<collection>/` 直下のサブディレクトリ（`conflicts`・隠しディレクトリを除外したロケールディレクトリ）を走査し、各 `<locale>/{draft,published}/*.md` を列挙する（`includeConflicts: true` 時は `<collection>/conflicts/*.md` も従来どおり列挙）。
  - `findLocalFilesByUlid()`・`resolveCanonicalArticlePath()`（`locale` 必須化）を `<collection>/<locale>/{draft,published}/` 対応へ更新。
- **Layer 2（全呼び出し元・競合/削除/剪定経路・3 階層相対メディアパス検証）**:
  - `src/sync/new.ts`（`createArticleScaffold`, `findLocalDuplicateSlug`, `resolveTranslationSource`）、`src/sync/push/commit.ts`、`src/sync/pull/{index,fast_path,snapshot_pull}.ts`（prune 経路含む）、`src/sync/orchestrator.ts` で `locale` を明示渡しして正規パスを計算。
  - **`src/sync/conflicts.ts`（必須修正）**: 2 階層固定（`path.join(collection, 'published', ...)` やパスからの `draft/published` 推定）を `<collection>/<locale>/{draft,published}/` 構造へ更新し、`emit conflicts diff / resolve` が新レイアウトで正しく動作するようにする。あわせて `src/sync/delete.ts` の退避バックアップ生成・パス解決も 3 階層前提で監査・修正する。
  - `localizeArticleMediaRefs()`（`src/utils/media-body-refs.ts` — 既存実装のまま深さ動的計算で対応済み）および `uploadAndRewriteDraftImages()` / `resolveFeaturedImageMediaId()`（`src/sync/push/media_stage.ts`）が 3 階層パス（`../../../media/<key>` および `../../../media/drafts/<file>`）を正しく処理することをテストで固定。
- **Layer 2 ([src/sync/doctor.ts](file:///Volumes/ext/github/emdash-emit/src/sync/doctor.ts))**:
  - `<collection>/draft/*.md`・`<collection>/published/*.md` の残存を検知する `legacy-flat-layout` チェック（`warn`）を追加。

### Feature 2 (REQ-1): タクソノミー YAML への `locale` / `translationGroup` シリアライズ

- **Layer 1 ([src/sync/taxonomies.ts](file:///Volumes/ext/github/emdash-emit/src/sync/taxonomies.ts))**:
  - `TaxonomyTerm` に `translationGroup?: string` を追加（`locale?: string` は既存）。
  - `pullTaxonomies()` がサーバーレスポンスから `locale` および `translationGroup ?? translation_group ?? translationGroupId` を抽出し、`categories/<id>-<name>.yaml`・`tags/<id>-<name>.yaml` へシリアライズする（ファイル名は ID 先頭のため複数ロケールで同一スラッグでも衝突しない）。
  - ローカルの `categories/*.yaml` / `tags/*.yaml` から `TaxonomyTerm[]`（`id`, `slug`, `locale`, `translationGroup`）を読み出す純粋ヘルパー `loadLocalTaxonomyTerms(workspaceRoot)` を追加。

### Feature 3 (REQ-2): `emit new --translation-of` のカテゴリ・タグ Auto-Map

- **Layer 2 ([src/sync/new.ts](file:///Volumes/ext/github/emdash-emit/src/sync/new.ts))**:
  - `CreateArticleOptions` に `inheritTaxonomies?: boolean`、`noTaxonomies?: boolean` を追加。
  - `translationOf` 指定時、明示的な `categories` / `tags` が渡されていない場合の自動解決優先順位：
    1. `noTaxonomies: true` → 強制的に空配列 `[]`。
    2. `inheritTaxonomies: true` → ロケール一致を問わず元記事の `categories` / `tags` をそのままコピー。
    3. **デフォルト（Auto-Map）**:
       - `loadLocalTaxonomyTerms()` を使い、元記事のタームが持つ `translationGroup` と一致するターゲット `--locale` のタームを検索し、その `slug` を自動割り当て。
       - 翻訳ペアが見つからない場合、ターゲット `--locale` 側に同一 `slug`（小文字正規化比較）のタームが存在すれば自動引き継ぎ。
       - いずれにも該当しないタームはスキップし、未マッピングのターム名を `warnings` でユーザーに通知する。
- **Layer 3 ([src/cli/commands/new.ts](file:///Volumes/ext/github/emdash-emit/src/cli/commands/new.ts), [src/mcp/tools/sync-new.ts](file:///Volumes/ext/github/emdash-emit/src/mcp/tools/sync-new.ts))**:
  - CLI: `--inherit-taxonomies` / `--no-taxonomies` オプションを追加。
  - MCP: `sync_new` に `inheritTaxonomies?: boolean` / `noTaxonomies?: boolean` を追加。

### Feature 4 (REQ-4): `emit status --i18n` ＆ MCP `sync_status` 翻訳カバレッジ可視化

- **Layer 1 ([src/sync/status.ts](file:///Volumes/ext/github/emdash-emit/src/sync/status.ts))**:
  - `ArticleStatusItem` に `locale: string` と `translationGroup?: string` を追加。
  - `buildTranslationCoverage(items, knownLocales?)` ヘルパーを追加し、`translationGroup || id` で記事をグルーピングした `TranslationCoverageGroup[]`（`translationGroup`, `slug`, `locales: Record<string, ArticleStatusItem | 'missing'>`）を 0-HTTP で構築する。
- **Layer 3 ([src/cli/commands/status.ts](file:///Volumes/ext/github/emdash-emit/src/cli/commands/status.ts), [src/mcp/tools/sync-status.ts](file:///Volumes/ext/github/emdash-emit/src/mcp/tools/sync-status.ts))**:
  - CLI: `emit status --i18n` を追加し、翻訳グループごとの各言語ステータス（`🟢 published (synced)` / `🟡 draft (modified)` / `⚪ missing`）をツリー表示する。
  - MCP: `sync_status` に `i18n?: boolean` を追加し、`true` 時に `translationCoverage` を返却する。
