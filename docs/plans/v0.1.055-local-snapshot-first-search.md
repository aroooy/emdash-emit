## 1. 背景と目的

v0.1.42〜v0.1.47 にかけて追加された検索機能には、現在以下の 3 系統が混在している：

1. **ローカル ＋ Snapshot オフライン検索**（`searchLocalArticles`, `searchLocalMirrorMedia`）
2. **オンライン FTS 検索**（`/_emdash/api/search` — 記事のキーワード単体時のみ）
3. **オンライン REST API ページング走査（Scan）**（`executeScanSearch`, `searchRemoteMedia` — `--max-scan` 300 / 50 / 500 件打ち切り ＋ `[WALK_INCOMPLETE]`）

特に **3. ページング走査（Scan）** は、フィルタ（`--tag` / `--category` / `--since` / `--status`）や日本語 3 文字未満の 0 件時に**暗黙に切り替わり**、5,000 件規模のブログでは常に規定上限で打ち切られて不完全な結果になるため、ユーザーと AI エージェント双方に高い認知負荷を生んでいた。

**v0.1.55 の目的**:

1. **REST API ページング走査検索を完全廃止**し、`--max-scan` / `maxScan` / `[WALK_INCOMPLETE]` の概念・実装・表面ドキュメント（`README.md`, `AGENTS.md`, `docs/*`, CLI/MCP）を一掃する（`CHANGELOG.md` の過去履歴はそのまま保持）。
2. **検索の主座を「ローカル ＋ Snapshot（`cache.db`）の 100% 全件検索（0-HTTP）」に一本化**し、サーバー上の最新記事をキーワード単体で即時確認したい場合のみ **`--live` / `live: true`（記事 FTS 専用）** を明示選択する明快な 2 モードへ整理する。
3. **AI-First `snapshotStatus` フレーミング**を導入し、ユーザーが Emit の内部構造を知らずに「◯◯を検索して」と指示した場合でも、AI がスナップショット未取得（`missing`）や鮮度低下（`stale`）を検知してユーザーへ適切な案内・次手提案を行えるようにする。

## 2. 設計原則（3 つのルール）

- **原則 1: 暗黙のページング打ち切りゼロ（No Bounded Scan）**
  - 「検索（`article-search` / `media-search`）」を名乗る全経路は、**常に母集団の 100% を対象に検索**する。
  - デフォルト（ローカル ＋ Snapshot）は `posts/` / `media/` と `.emit/cache.db` 全行を走査する。
  - `--live`（記事 FTS）は EmDash サーバー側の全文インデックス全体に対して問い合わせる。
  - 途中で打ち切って `[WALK_INCOMPLETE]` で補う設計は廃止する。
  - **Search と Diagnostic Census の境界（P3）**: `emit doctor --check-media-library` が用いる `fetchMediaListPage()`・`collectRemoteStorageKeys()`・`findUnmirroredStorageKeys()` は「検索」ではなく診断（census）用途であるため維持し、`AGENTS.md` 原則 6 にその境界を明文化する。

### 原則 2: 明示的な 2 モード分離（Snapshot-First Default vs Explicit `--live` FTS）

| コマンド / ツール                             | デフォルト（0-HTTP・トークン不要）                                                                                                | `--live` / `live: true`                                                                                                                                                                                           |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `emit article-search` / `sync_article_search` | ローカル `posts/` ＋ `snapshot_articles` を **100% 全件検索**（キーワード・`tag`・`category`・日付・`status`・`slug` すべて対応） | サーバー `/_emdash/api/search`（FTS）を直叩き。**`tag`/`category`/`since`/`until`/`status` 指定時やクエリ空欄時は暗黙フォールバックせず即エラー**（`LIVE_SEARCH_UNSUPPORTED_FILTER`）を返し、デフォルト検索を案内 |
| `emit media-search` / `sync_media_search`     | ローカル `media/` ＋ `snapshot_media` を **100% 全件検索**（`--mirrored-only` 時は `media/` のみ）                                | **設けない**（EmDash 側にメディア FTS が存在しないため、常にローカル ＋ Snapshot）                                                                                                                                |

- `--offline` / `offline` は「デフォルト自体がローカル ＋ Snapshot（0-HTTP）になった」ため、CLI/MCP インターフェースから削除する。
- `emit article-search`（`--live` なし）および `emit media-search` は `resolveContext(options.profile, { optionalAuth: true })` とし、認証トークン無しでも動作する（MCP 側は `server.ts` の既存方針どおり `resolveContext` 必須を維持）。

### 原則 3: AI-First `snapshotStatus` フレーミング（`fresh` / `stale` / `missing`）

デフォルト検索（ローカル ＋ Snapshot）の結果には、CLI/MCP 共通の判定ロジック（`src/presentation/`）で算出した鮮度・カバレッジ状態を必ず付与する：

| `snapshotStatus` | 判定条件                                       | `userNotice`（ユーザー向け説明）                                                                | `recommendedAction`（AI の次手）                                                                                  |
| ---------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **`fresh`**      | `snapshot_meta` あり & `ageDays < 7`           | なし（通常の全件検索として回答）                                                                | なし                                                                                                              |
| **`stale`**      | `snapshot_meta` あり & `ageDays >= 7`          | `{ageDays}日前のスナップショットから検索したため、それ以降の変更は含まれない可能性があります。` | `sync_snapshot(action: "capture")` で最新化、または記事キーワード単体なら `live: true` でライブ確認               |
| **`missing`**    | `snapshot_meta` なし（ワークスペースのみ検索） | `全件スナップショットが未取得のため、手元のワークスペース内のみを検索しました。`                | `sync_snapshot(action: "capture")` で全件インデックスを作成するか確認（記事キーワード単体なら `live: true` も可） |

- **`absenceGuaranteed` と `limit` トランケーションの語義分離（P2）**:
  - **母集団の 100% 走査**と **返却件数上限 `limit`（既定 20、最大 50）** は別軸として扱う。
  - `absenceGuaranteed: boolean`: `hits.length === 0` のときの不在保証を表す（デフォルト検索で `snapshotStatus === 'fresh'` なら `true`、`'stale'` / `'missing'` なら `false`。`live` FTS でクエリ 3 文字未満または `nextCursor` 残存時も `false`）。`hits.length === 0` かつ `absenceGuaranteed === false` の場合、断定を避け `recommendedAction` を返す。
  - `truncated: boolean` / `totalCount`: マッチ件数が `limit` を超えた場合（Snapshot 側 `totalCount > hits.length`、または Live FTS 側 `nextCursor` 存在時）は `truncated: true` を返し、CLI/MCP ともに「上限 `limit` で表示を切った（`--limit` / `limit` を上げると続きが見られる）」旨の more-hints を表示する。
- **MCP `server.tool` の `description`**:
  - `sync_article_search` / `sync_media_search` の `description` に、`snapshotStatus` が `"missing"` または `"stale"` のときにユーザーへカバレッジ／鮮度を説明し、必要に応じて `sync_snapshot(action: "capture")`（または記事キーワードなら `live: true`）を提案する行動指針を明記する。

## 3. 変更設計の詳細

### 3.1 コア層（`src/sync/article_search/`, `src/sync/media/`）

1. **`src/sync/article_search/remote.ts` → Live FTS 専用へ簡素化（P1・P5）**:
   - Scan 専用の関数・定数・型（`executeScanSearch`, `readTaxonomiesFromBaseline`, `BaselineTaxonomyRead`, `MAX_TAXONOMY_REMOTE_FETCHES`）をすべて削除する。
   - `searchRemoteArticles(options)` は公開互換シンボルとして維持し、`!options.live` なら `searchLocalArticles(options)` へ委譲、`options.live === true` なら FTS（`/_emdash/api/search`）のみを実行する：
     - `query` が空、または `tag`/`category`/`since`/`until`/`status` が指定されていれば `ApiError(LIVE_SEARCH_UNSUPPORTED_FILTER, status: 400)` をスローする。**ガイダンス文言は CLI/MCP 共通の「フィルタを使う場合はデフォルト検索（`--live` / `live` を外す）を使用してください」に統一する（P4）。**
     - **Snapshot Enrichment と Cursor Truncation の維持（P1）**: `live` FTS ヒットに対する `getSnapshotArticle()` による `status`/日付補完・`isSameRev()` 検証（`enrichedFromSnapshot`, `enrichmentStale`）、および `nextCursor` による `truncated` / `walkComplete = !nextCursor` 判定はそのまま維持する。
     - `/_emdash/api/search` が HTTP エラーを返した場合は Scan フォールバックせず `ApiError(ARTICLE_SEARCH_FAILED)` をスローする。
     - 日本語 3 文字未満での 0 件時 Scan フォールバックも削除し、trigram 制約による取りこぼし可能性がある旨の `userNotice`（デフォルト検索を案内）を返す。
2. **`src/sync/article_search/types.ts`**:
   - `ARTICLE_SEARCH_DEFAULT_MAX_SCAN` / `ARTICLE_SEARCH_TAXONOMY_MAX_SCAN` と `ArticleSearchOptions.maxScan` / `offline` を削除し、`live?: boolean` を追加。
   - `ArticleSearchResult.searchMode` を `'local' | 'fts'` へ整理。
3. **`src/sync/media/remote_index.ts` & `src/sync/media/types.ts`**:
   - `searchRemoteMedia()`・`MEDIA_SEARCH_DEFAULT_MAX_SCAN`・`SearchRemoteMediaOptions` を削除。
   - `fetchMediaListPage()` と `collectRemoteStorageKeys()`（および `findUnmirroredStorageKeys()`）は `pull_library.ts` / `snapshot/index.ts` / `doctor.ts` が診断・同期に利用するためそのまま保持（P3）。
4. **`src/sync/guards.ts`**:
   - `OPERATIONAL_ERROR_CODES` と `REMEDIATION_MAP` に `'LIVE_SEARCH_UNSUPPORTED_FILTER'` を追加（Rule 2 網羅性維持）。

### 3.2 Presentation 層（`src/presentation/`）

- **`src/presentation/article_report.ts` & `src/presentation/media_report.ts`**:
  - `formatArticleSearchWalkIncompleteNotice`・`formatMediaSearchWalkIncompleteNotice` を削除。
  - **共有フレーミング関数 `buildSnapshotSearchFraming()`（軽微 1）**: `result.snapshot`, `result.hits.length`, `result.truncated`, `result.walkComplete`, `{ isLive, query }` を受け取り、`SnapshotSearchFraming`（`snapshotStatus: 'fresh' | 'stale' | 'missing'`, `ageDays?`, `capturedAt?`, `absenceGuaranteed: boolean`, `truncatedHint?: string`, `userNotice?: string`, `recommendedAction?: string`）を返す純粋関数を `src/presentation/` に配置し、CLI と MCP の双方で共有する（Axis 3 遵守）。
  - `formatArticleSearchHeader` / `formatMediaSearchHeader` / `formatArticleSearchEmptyNotice` / `formatMediaSearchEmptyNotice` から `--max-scan` / `[WALK_INCOMPLETE]` / `--offline` 前提の文言を除去し、`buildSnapshotSearchFraming()` ベースの表示および `truncated` 時の more-hints（P2）へ統一する。

### 3.3 CLI / MCP 層（`src/cli/`, `src/mcp/`）

- **CLI（Breaking Change）**:
  - `src/cli/commands/article-search.ts`: `--max-scan`・`--offline` を削除（Commander が unknown option として拒否）、`--live` を追加。`resolveContext(options.profile, { optionalAuth: !options.live })`。
  - `src/cli/commands/media.ts`: `--max-scan`・`--offline` を削除。`resolveContext(options.profile, { optionalAuth: true })`。
- **MCP（Breaking Change）**:
  - `src/mcp/tools/sync-article-search.ts`: `maxScan`・`offline` スキーマを削除、`live: z.boolean().optional()` を追加。`description` に `snapshotStatus`（`missing` / `stale`）時および `live` 3文字未満 trigram 制約時の案内ルールを明記。レスポンス JSON に `buildSnapshotSearchFraming()` の全フィールド（`snapshotStatus`, `absenceGuaranteed`, `userNotice`, `recommendedAction` 等）をマージ。
  - `src/mcp/tools/sync-media-search.ts`: `maxScan`・`offline` スキーマを削除。`description` に `snapshotStatus` 案内ルールを明記し、レスポンス JSON に `buildSnapshotSearchFraming()` をマージ。
  - MCP の `withResolvedContext` は従来通り auth 必須（`server.ts` 方針踏襲）。
