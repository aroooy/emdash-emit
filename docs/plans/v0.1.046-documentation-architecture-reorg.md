## 1. 背景と目的

v0.1.12 から v0.1.45 までの 30 回以上にわたる迅速な機能改善・リファクタリングにより、コードベース（`src/` 118 モジュール、テスト 72 ファイル / 892 tests 全 green）は 4 層アーキテクチャと自動品質ゲート（`tests/layering.test.ts`, `tests/guards.test.ts`）によって極めて高い整合性を保っている。

一方で、各バージョンの改修仕様や不変条件（Invariant）をその都度 `README.md`、`AGENTS.md`、および `docs/v01xx-*` に追記してきた結果、ドキュメント体系に以下の課題が生じている：

1. **`README.md` の肥大化（1,322 行 / 約 80KB）**:
   - リポジトリの「看板（導入・コンセプト・基本操作）」と「全 CLI/MCP オプションの完全リファレンス」と「内部 SQLite スキーマ・エッジケース仕様」が 1 ファイルに混在しており、人間にとって通読困難な状態になっている。
2. **`AGENTS.md` の実装ノート堆積（359 行 / 約 52KB）**:
   - 「記事執筆 AI エージェント向けの運用ルール」と「Emit 開発者/AI 向けのアーキテクチャ憲法」が混在し、後半には過去のバグ経緯や関数・行番号単位の細かな実装ノートが 1 段落数千文字の箇条書きとして蓄積している。
3. **`docs/` 直下の計画書乱立とソート崩れ（移動対象 36 アイテム：計画書フォルダ 33 個 + バックログ 2 ファイル + 過去設計書 1 ファイル ＋ 本計画書 1 ファイル = 計 37 アイテム）**:
   - `docs/` 直下に `v0112-eval` 〜 `v0145-refactor-plan` が並び、何の計画書か名前から判別できない。
   - 中身が `README.md` 1 ファイルのみのフォルダが 28 個あり、エディタで開くとすべて `README.md` タブになって識別しづらい（複数ファイルを持つフォルダは `v0112`, `v0113`, `v0114`, `v0116`, `v0131` の 5 個）。
   - 現在のシステム仕様を示す「境界（ドメイン）ごとの詳細設計書」が `media-id-spaces.md` 以外に存在せず、最新の全体仕様を把握するには `AGENTS.md` と過去の計画書を横断して読む必要がある。

### 本計画のゴール

1. **過去計画書・バックログの `docs/plans/` への集約と案 A（SemVer ゼロ埋め + トピック名 + 単一ファイルフラット化）による再命名**
2. **`docs/` 直下への「プログラム境界ごとの詳細設計書（正典 Specifications）」の新設**
3. **`AGENTS.md` の「アーキテクチャ憲法＋コア不変条件＋例外台帳ルール＋開発ガバナンス」へのスリム化（詳細仕様は `docs/` 正典へ移管・リンク）**
4. **`README.md` の「看板（導入・コンセプト・クイックスタート・コマンド概要一覧）」への再構成（全 13 H2 セクションを情報欠落ゼロで `docs/` へ移管・再配置）**
